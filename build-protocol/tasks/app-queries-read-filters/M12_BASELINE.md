# M12 read-boundary and history baseline

Source checkpoint: `cc19b416d`. Read-only inventory for M12; no code/tests/builds were changed or run. The current tree includes concurrent edits from other milestones; this note does not infer their completion.

## Contract and caller directions

`MILESTONES.md:378-400` requires BC filters on public/internal BC read boundaries and Server filters only on Entity/App Query output leaving gRPC. It explicitly includes direct Stand reads and retained Entity/Agent state/Event history, while excluding hydration/restoration/replay and persistence maintenance. The proposal’s caller-flow diagrams and cursor requirement are `PROPOSAL.md:451-472`; its distinction is: Server query/handler source read → BC filter, then final App Query result → Server filter; direct internal Entity read → BC filter only; BC history retains the original cursor even for an empty filtered page. Stored state, Event history used by runtime, replay, and restoration must not be redacted.

## Current-state Entity reads

- Public native Query path: `packages/server/src/services/spine-services.ts:397-478` validates and routes `QueryService.Read`; `:448-470` resolves tenant and plan; `:453-465` calls `QueryReader.read(...)` and packs versioned states into `QueryResponse`. QueryReader in `packages/server/src/services/query-reader.ts:23-77` invokes `Stand.queryPlanVersioned` and optionally reports an observed Query for tests. This is the current Server gRPC read boundary and its direct storage-read route.
- Direct Stand APIs: `packages/server/src/stand/stand.ts:380-422` (`read`/`readVersioned`), `:432-469` (`readAllVersioned`/`queryVersioned`), and `:480-500` (`queryPlanVersioned`) return current state messages or `{state, version}` snapshots. Their callers include Server QueryReader and repository code; the same methods are directly invoked by application/test code through a context’s Stand (e.g. `packages/server/test/context/bounded-context.test.ts:1641`). A BC-level interception below `QueryReader` is needed to cover both routes, but repository restoration also uses Stand access and must retain raw state.
- Process Manager/Agent handler reads: `packages/server/src/entity/entity.ts:1306-1310,1360-1430` exposes protected `select` APIs. `EntityQueryReads.select` (`:160-195`) binds detached queries to the active actor/tenant, and `packages/server/src/repository/repository.ts:4070-4120` resolves registered targets then reads through Stand; this is an internal handler source read and returns state messages to the handler, not gRPC output. Filter context must preserve the active request/actor/tenant and enclosing AppQuery where applicable (proposal `:399-404`).
- Restoration/hydration is distinct: repository Aggregate/Projection loading reads current state through `standAccess.readCurrent` before instantiating the entity (`packages/server/src/repository/repository.ts:2685-2722,3590-3665`; Projection loader around `:3970-4120`). Repository boot and replay invoke repository execution on stored commands/events (`:11269-11824,12302-12516`), and `BoundedContext.catchUpReadSide` clears projection records then reads stored Events and dispatches replay (`packages/server/src/context/bounded-context.ts:1736-1795`). These inputs reconstruct authoritative state/behavior and are not returned read views.

## Retained Entity state/Event history

- Entity diagnostic methods are protected: `packages/server/src/entity/entity.ts:650-688` (`stateAt`, `stateHistoryBackward`) and `:1207-1270,1306-1365` (Aggregate/Process Manager diagnostic Event-history readers; Projection intentionally lacks these methods). `EntityHistoryAccess` at `:706-808` binds repository-backed reads and separate maintenance ports. `RepositoryEntities.bindEntityHistory` (`packages/server/src/repository/repository.ts:10320-10430`) exposes `stateAt`, states, and Events; `RepositoryHistoryInternals.readBoundStateAt/readBoundStates` (`:10445-10490`) returns detached state snapshots. Event history read helpers follow nearby in the same module. These history results are observations for entity/application code; the storage/cache they read must remain intact.
- Repository public Agent history: `packages/server/src/repository/repository.ts:288-320` declares `AgentHistoryReader` returning full entries, ConversationRecords, or Events; `Repository.agentHistory` (`:970-990`) returns that reader without restoring an Agent. `RepositoryAgentReads.history` (`:1084-1110`) captures repository, ID, explicit tenant scope and creates four category views. `historyPage` (`:1120-1160`) performs provider reads and preserves `nextCursor`; `project` (`:1163-1176`) exposes conversation/system/domain payloads while preserving continuation. Agent history messages therefore include `AgentHistoryEntry`, `ConversationRecord`, and `Event`.
- Agent protected façade: `packages/server/src/entity/entity.ts:1435-1520` maps `fullHistory`, `conversationHistory`, `systemEventHistory`, and `domainEventHistory` to `AgentHistoryReads`; current invocation interception is `packages/server/src/agent/agent-history.ts:36-72,120-205,356-417`. Live read mediation is installed around handler execution at `packages/server/src/repository/repository.ts:5047-5068`; avoid applying a returned-view filter to provider write/append, runtime audit, or replay paths.
- History cursors/order: Agent cursor encodes scope, view and order key (`agent-history.ts:492-540`); page output uses the last entry for continuation (`:464-489`). Entity state-history cache in `repository.ts:10570+` pages by version. M12 filtering can make `items` empty while leaving the provider-produced continuation byte/value unchanged, per proposal `PROPOSAL.md:472`.

## Methods that must remain unfiltered

Do not indiscriminately wrap `Stand.read/readVersioned/queryVersioned/queryPlanVersioned`: all are used for ordinary reads, but the repository also uses low-level current-state access for Entity restoration and handler reconstruction. Keep raw reads for `standAccess.readCurrent`, repository loading/hydration, projections being populated by stored Events, Inbox replay, `catchUpReadSide`, and persistence maintenance (trim/truncate/clear/delete/append). In particular, Event history used for Aggregate/Process Manager behavior and Agent runtime audit/replay is not merely an outward read page. Filter only the concrete returned-view boundaries identified in the proposal: BC reads (including explicit direct Stand/context reads and protected/public history reads) and Server gRPC Entity/App Query outputs.
