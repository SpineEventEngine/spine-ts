## Findings

- **P2 — Lifecycle validation misses a rejected Topic criterion.** `packages/server/src/services/spine-services.ts:638-649` returns immediately for every criterion except `filters`. `Activate` and `Cancel` call this method before lookup or mutation (`:505-514`, `:622-631`), so a complete `Subscription` containing `criterion: { case: "includeAll", value: false }` passes their admission checks. The same Topic is rejected by Subscribe's `createSubscriptionShape()` at `:1623-1631`; the Subscribe test at `packages/server/test/services/spine-services.test.ts:3573-3582` establishes that declared validation accepts the selected false oneof and the semantic check rejects it. An unknown cancellation can therefore return OK, and a known ID can reach cancellation, for a request shape that Subscribe would refuse. Apply the same usable-criterion semantic rule to lifecycle requests before record access, with Activate/Cancel regressions for false `includeAll` and no lifecycle mutation.
- **P3 — Remove the obsolete successful Query error-response path.** After `#read()` changed to throw structured RPC errors, `packages/server/src/services/spine-services.ts:1108-1116` leaves `errorResponse()` and `queryErrorResponse()` with no call sites; only `queryErrorResponse` remains listed in the local `ServiceValues` object at `:2379`. Those helpers encode the previous success-response error contract and can mislead the next service change. Delete both and the object entry when correcting this slice.
