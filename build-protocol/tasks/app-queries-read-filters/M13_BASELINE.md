# M13 subscription-delivery baseline

Source checkpoint: `54520ee63`. Read-only inventory; M04 lifecycle/client corrections are in progress concurrently, so this describes the observed checkpoint only. No source/tests were changed or run.

## M13 contract anchors

`MILESTONES.md:403-428` requires original Topic matching, then BC filtering, then Server filtering; preserve Entity ID/version separately from mutable state; root-null becomes existing `no_longer_matching`; prior removal notices pass through. Event filters operate on root domain payloads, retain envelope metadata, suppress only this consumer's null Event, and omit empty data batches while preserving control updates. Preserve grouped Event child BC/context, bounded queues/order, and cancel/error behavior. Proposal detail: `PROPOSAL.md:429-436,508-556,558-596`.

## Source-to-delivery paths

1. **BC observers classify and render** — `packages/server/src/stand/subscription-runtime.ts:65-92,383-411` keeps one attachment per subscription ID and consumer callbacks by ID. It checks state target metadata in domain Stand; known state targets use `observeState` on the paired System EventBus, otherwise Event targets use `observeEvent` on the domain EventBus. The observer itself retains the subscription Topic and tenant context.
2. **Entity state matching/removal** — `packages/server/src/stand/subscription-observer.ts:160-230` observes state-change and archive/delete/unarchive/restore System Events. `:410-434` unpacks the System Event's `EntityStateChanged` data into detached `StandUpdate` containing `id`, prior state, new state, new `version`, and tenant; `:449-470` applies original Topic ID/field criteria to new state and previous state. Match yields state or no-longer-matching. `:343-394` constructs a one-item public `EntityStateUpdate`, packing ID from `update.id` and state from `update.state`; if matching transitions away, existing renderer emits `kind.noLongerMatching`. Archive/delete use `:275-363`; the removal notice carries only original ID and control case, no mutable domain state. Thus read-side state filtering must retain the observer's original `id` and `version` independently and must preserve existing removal notice cases.
3. **Event delivery root/envelope** — `SubscriptionObservers.observeEvent` (`subscription-observer.ts:124-147`) subscribes by Event type URL on the domain EventBus, applies tenant and origin criteria against the original Event (`:132-145`), then emits a cloned Event inside `EventUpdates.event` (`:397-407`). Event envelope includes ID/context/metadata plus Any `message`; the filter root for M13 is the decoded domain `message` payload. `#cloneClientEvent` (`:620-630`) scrubs sensitive rejection-only fields from the outward copy. Filtered payload therefore needs to be repacked into a copied Event while leaving stored/dispatch source intact.
4. **BC/source route** — `packages/server/src/services/spine-services.ts:203-215` builds Event routes from each context's externally accepted domain schemas. `:659-671` resolves target type to the state/Event route; `:673-684` attaches this route's context subscription runtime. The selected Event route therefore carries the producing BoundedContext for the target type. Grouped Events use one Topic per Event schema, and each Topic resolves independently to its own route/BC; client grouping must not flatten away each member's metadata/context.
5. **Server RPC attachment and streaming** — `spine-services.ts:473-511` creates a new native Subscription ID with a cloned Topic; `:512-530` activation yields readiness ACK then queued updates, and on stream closure invokes removal. `:673-684` forwards updates into that subscription record's delivery queue. `SubscriptionDelivery` (`:942-1047`) is FIFO with configured queue cap; overflow closes and detaches. `spine-services.ts:859` sets queue limit to 100; mutation/cancel cleanup is around `:686-750`.
6. **Managed Coordinator fan-out** — `packages/server/src/server/node-coordinator.ts:447-467` creates a logical subscription and fans its definition to backend members. `:479-537` activates child streams and changes each relayed update's subscription field to the original logical Subscription after child processing. `NodeCoordinatorValues.childDefinition` around `:831-845` gives each member a distinct child ID suffix while preserving its Topic. `activateChild` (`:933-957`) checks each child update ID and exact Topic equality before forwarding. `SubscriptionUpdateQueue` (`:687-766`) is FIFO, capacity 100, backpressures producers until a consumer pulls queued data, and closes/aborts on overflow. Public cancel/activation cleanup is `:561-565,539-558`.
7. **Browser client/grouping/cancel** — `packages/client-web/src/client/client.ts:2532-2570` creates a new UUID Topic ID and clones actor context for every distinct Event schema; `:930-979` creates one `TopicSubscription` per Topic or a `GroupSubscription` of one member per Event schema. `GroupSubscription` (`:2093+`, especially `:2130-2210,2250-2320`) combines member streams into bounded output channels; member errors fail/cancel siblings. `TopicSubscription` owns one wire Topic and reconnect state (`:1342+`). Cancel closes local delivery and coordinates remote cancellation; relevant portions around `:1560-1580,1722-1775` and group cancel thereafter. Per-consumer isolation begins with separate Topic IDs and separate server subscription records; do not mutate a shared Event/Entity message before fan-out.

## Event persistence and internal delivery boundary

- Public Event subscriptions target accepted **domain** Event schemas. `packages/server/src/bus/event-bus.ts:341-354,399-432` clones posted Events, validates/admit-checks, calls the EventStore `acceptThenAppend`, then delivers the accepted stored snapshot to dispatchers; direct subscriber notifications clone the Event (`:620-625`). M13 filtering is a subscriber delivery view and must not alter the Event passed to storage, domain handlers, other subscribers, or replay.
- Framework state changes and lifecycle messages use a paired System EventBus (`subscription-observer.ts:150-230`); they are inputs used to render public Entity-state subscription updates, not public domain Event subscriptions. Service route construction excludes internal Event schemas (`spine-services.ts:203-215`; topic target rejection `:659-668`). M13 must not change persisted Events, handler inputs, EventStore replay, projection hydration/catch-up, or protocol control/activation ACKs. M12 separately filters returned Entity/Agent history views; that outward-read behavior is not a reason to alter persisted history or runtime replay inputs.
- Event-origin criteria use `EventOriginFilters.compile` before Event rendering (`subscription-observer.ts:132-145`). Existing criteria should stay based on the original envelope/payload, before filter replacements mutate a detached copy.

## Queue/order/cancellation seams

- `SubscriptionRuntime.#notify` (`subscription-runtime.ts:427-446`) iterates consumers for one ID and currently invokes callbacks without awaiting returned promises; failures are isolated/logged. `#removeConsumer`/handle unsubscribe is `:363-381`; detach unsubscribes the EventBus/Stand observer (`:263-273`). Async read-side filter work cannot be allowed to reorder updates or keep delivering after cancellation.
- Native per-subscription FIFO/capacity is `SubscriptionDelivery` (`spine-services.ts:942-1047`); Coordinator per-public-stream FIFO/capacity is `SubscriptionUpdateQueue` (`node-coordinator.ts:691-766`). Client `BoundedChannel` retains update count and byte bounds (`client.ts:1760-1775` and construction in `:2125-2139`); group has independent lifecycle and update queues. These are existing backpressure/overflow surfaces.
- All-removal Event batches must not erase activation ACK or other SubscriptionUpdate control cases: Server emits ACK before reading `record.delivery.next()` (`spine-services.ts:512-525`). Entity `no_longer_matching` remains an ordinary removal notice for the subscription consumer. Authoritative Entity query recovery is a separate client gap-recovery path (`packages/client-web/src/client/client.ts:1187+`); M13 does not add a prior-query dependency or global client-cache mutation. Event stream does not synthesize replay.
