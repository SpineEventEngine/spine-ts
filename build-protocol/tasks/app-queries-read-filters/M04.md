## Implementation and evidence (2026-10-30)

The pinned JVM `Stand.activate` validates registry support before activation,
and `SubscriptionValidator.checkInRegistry` rejects a missing ID through
`InvalidSubscriptionException`; `SubscriptionService.ActivationImpl` forwards
that failure. This informed the missing/expired distinction, while the approved
TypeScript contract supplies `NOT_FOUND` and the enum-qualified structured
`spine.client.SubscriptionValidationError.UNKNOWN_SUBSCRIPTION` status. The
service still validates malformed Subscribe/Activate inputs first. Registry
missing and expiry now raise the structured status; duplicate active delivery
and closed delivery keep their prior distinct behavior. Valid unknown Cancel
remains idempotent. Native gRPC carries matching Connect detail and
`spine-error-bin`, and the Coordinator forwards a child unknown reason intact.

The browser client's existing bounded recovery loop now explicitly recognizes
that exact type and numeric enum reason for `NOT_FOUND`, obtaining a fresh
server-issued ID. Other `NOT_FOUND`, invalid, denied, unauthenticated, and
tenant-unknown statuses terminate. Transient transport statuses and unexpected
stream endings retain bounded retry. Event reconnection emits `gapPossible`;
Entity reconnection performs its authoritative query. Cancellation during
backoff prevents a later RPC, and exhausted replacement attempts surface the
terminal error. Current API and browser reference text reflects these rules.

Behavior-first red tests: registry-missing/expired activation failed because
the stream completed inertly; four client status cases failed because each
created three subscriptions instead of one. After implementation, those tests
passed. The final full affected `spine-services`, `node-coordinator`, and
browser-client suites passed **291/291** tests. They cover native unknown and
expired activation, native trailer/details, duplicate activation races,
idempotent unknown Cancel, Coordinator child forwarding, fresh-ID recovery,
Entity authoritative read, Event gap notice, cancellation during unknown
recovery backoff, exhausted retry, and terminal status distinctions.

`pnpm typecheck:build:generated` passed after the final runtime change.
