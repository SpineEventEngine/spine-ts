## Objective

Use the package-internal retained-attempt summary and retry-decision primitive to
avoid invoking supported endpoint callbacks after a message has exhausted its
bounded retry budget, while leaving public monitor/action policy for later.

## Scope

- Add a package-internal retry-exhaustion gate in the delivery drain path.
- Summarize retained attempts for one exact supported endpoint message before
  endpoint callback invocation.
- Apply `DeliveryRetryDecisions` with a bounded internal maximum-attempt budget.
- Skip endpoint callback invocation when the retained count is exhausted.
- Keep exhausted rows pending `TO_DELIVER` for later public monitor,
  dead-letter, or mark-delivered policy.
- Avoid recording another retained attempt for an already exhausted row.
- Preserve current behavior for retryable supported rows.
- Preserve current worker-unsupported `CATCH_UP` pending/skip behavior and
  legacy malformed/deprecated `IMPORT_EVENT` fail-closed behavior.

## Out Of Scope

- Public `DeliveryMonitor`, `FailedReception`, repeat-dispatch, mark-delivered,
  or dead-letter APIs.
- Immediate retry, backoff, timers, scheduler ownership, worker supervision,
  production transport topology, production storage adapters, or cancellation
  policy.
- Any `CATCH_UP` execution semantics or catch-up storage.
- New `IMPORT_EVENT` support.
- Raw payload/error retention, stack traces, or unbounded exception text.
- Public end-user delivery APIs.

## Internal Policy Decision

Use the retained-attempt ring size, 100, as the initial internal maximum attempt
budget. This keeps T-0032 from inventing public configuration while aligning
the exhaustion boundary with the only durable retained history currently
available.

## Acceptance Criteria

- Supported endpoint rows with retained attempt counts below the internal
  budget behave as today.
- Supported endpoint rows with retained attempt counts at or above the internal
  budget do not invoke endpoint callbacks.
- Exhausted rows remain pending `TO_DELIVER`.
- Exhausted rows do not record another retained delivery attempt.
- Exhausted rows do not consume endpoint accepted-work `limit`.
- Exhausted rows are observable in the returned `DeliveryRun.failures` without
  exposing raw payload bytes, raw user errors, stack traces, or unbounded text.
- Exhausted exact-message drains use the same gate as shard drains.
- Unsupported valid labels such as `CATCH_UP` remain pending/skipped before
  callback invocation, acceptance, failure recording, and failure-budget
  consumption.
- Malformed/deprecated legacy `IMPORT_EVENT` stored rows remain fail-closed
  storage corruption.
- No public package export leaks retry monitors, failed-reception actions,
  backoff/scheduler policy, topology, catch-up, or production adapter APIs.
