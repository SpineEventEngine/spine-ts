## Concrete implementation pitfalls

1. **mysql2 defaults to matched-row reporting.** Installed `mysql2@3.23.1` source includes `FOUND_ROWS` in `ConnectionConfig.getDefaultFlags()` at `node_modules/.pnpm/mysql2@3.23.1_@types+node@24.13.2/node_modules/mysql2/lib/connection_config.js:227-231`. mysql2's `ResultSetHeader` parses protocol `affectedRows` separately from `changedRows` at `.../mysql2/lib/packets/resultset_header.js:28-30,99-104`. Therefore an UPDATE that matches a row but leaves its values unchanged can report `affectedRows === 1` under the default client flags. Do not use `affectedRows` alone as proof that bytes/state changed. MySQL 8.4 and MariaDB both document the distinction: without `CLIENT_FOUND_ROWS`, UPDATE reports changed rows; with it, matched rows. Sources: [MySQL 8.4 ROW_COUNT](https://dev.mysql.com/doc/refman/8.4/en/information-functions.html), [MariaDB ROW_COUNT](https://mariadb.com/docs/server/reference/sql-functions/secondary-functions/information-functions/row_count).

2. **Keep public CAS equality separate from the SQL race guard.** Public CAS compares decoded Protobuf values using the existing semantic equality contract; wire-distinct encodings can represent equivalent values. After that semantic comparison, a single guarded SQL `UPDATE` or `DELETE` can use the exact raw bytes observed during the read as its race guard. PostgreSQL `bytea` stores raw octets, including zero and non-printable bytes; MySQL/MariaDB `BLOB` is a binary string. Test empty bytes, embedded zeroes, trailing zeroes/spaces, and wire-equivalent observations. Avoid text casts/collations or fixed-width `BINARY(n)` padding. Current MySQL table schema uses `BLOB` (not `MEDIUMBLOB`/`LONGBLOB`), whose limit is 65,535 bytes; verify accepted serialized records stay within that existing bound or report it as a storage limit. References: [PostgreSQL 16 binary data](https://www.postgresql.org/docs/16/datatype-binary.html), [PostgreSQL 18 binary data](https://www.postgresql.org/docs/18/datatype-binary.html), [MySQL 8.4 BINARY/VARBINARY](https://dev.mysql.com/doc/refman/8.4/en/binary-varbinary.html), [MariaDB BLOB](https://mariadb.com/docs/server/reference/data-types/string-data-types/blob).

3. **A duplicate error code does not establish that the primary key conflicted.** PostgreSQL `23505` means any unique violation; `pg-protocol@1.16.0` exposes server `code` and `constraint` fields (`node_modules/.pnpm/pg-protocol@1.16.0/node_modules/pg-protocol/src/messages.ts:80-111`). Compare the reported constraint with the expected primary-key constraint where constraint identity is needed. MySQL/MariaDB `ER_DUP_ENTRY` / errno 1062 / SQLSTATE 23000 covers unique keys and primary keys; mysql2 exposes `code`, `errno`, `sqlState`, and `sqlMessage` at `.../mysql2/lib/packets/packet.js:827-837`. Do not swallow every 1062 as a CAS race. Use the server's constraint/key identity or an explicitly validated schema that has only the expected primary key; otherwise preserve and propagate the uniqueness failure. An occupied slot contains the competing value, so equality to the caller's expected bytes is not a valid way to classify a primary-key collision. Sources: [PostgreSQL 16 error codes](https://www.postgresql.org/docs/16/errcodes-appendix.html), [MySQL 8.4 server error 1062](https://dev.mysql.com/doc/mysql-errors/8.4/en/server-error-reference.html), [MariaDB error 1062](https://mariadb.com/docs/server/reference/error-codes/mariadb-error-codes-1000-to-1099/e1062).

4. **Nontransactional engines still require a one-statement guard.** Current MySQL storage detects `InnoDB`, `MyISAM`, and `Aria` in `packages/storage-mysql/src/mysql/record-storage.ts:618-697`; it treats only InnoDB as transactional. A rollback cannot undo MyISAM or Aria mutations, and MariaDB documents Aria `TRANSACTIONAL=1` as crash safety rather than multi-statement transaction support. These facts do not imply a need for an external read/write named lock: the semantic read followed by one SQL `UPDATE`/`DELETE` guarded by ID and observed raw bytes makes the mutation decision atomic at the statement boundary, including for nontransactional engines. On guard miss, reread and retry only within the specified fixed bound. Treat earlier statements as independently committed; do not claim rollback reverses them. References: [MySQL 8.4 MyISAM](https://dev.mysql.com/doc/refman/8.4/en/myisam-storage-engine.html), [MySQL 8.4 transaction tables](https://dev.mysql.com/doc/refman/8.4/en/performance-schema-transaction-tables.html), [MariaDB Aria engine](https://mariadb.com/docs/server/server-usage/storage-engines/aria/aria-storage-engine).

5. **Preserve typed errors when interpreting races.** Existing MySQL adapter wraps driver failures using `mysqlError`; PostgreSQL uses `operationError`. A primary-key race classifier should be narrow and should not turn non-primary uniqueness, deadlock, or connection failures into a false CAS result. Preserve the original driver cause for diagnostics and retry only the explicitly supported transient errors.
