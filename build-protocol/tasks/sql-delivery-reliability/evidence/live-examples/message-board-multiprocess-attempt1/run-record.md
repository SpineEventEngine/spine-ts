# Local Message Board multi-process live run

This run used the corrected local launcher with eight application processes and eight Delivery shards. The task-specific configuration was image tag `sqlrel-live-1014`, Datastore project `message-board-local-50ebfca9-818c-4d6f-9687-cd089cce67a1`, and loopback ports Delivery `28484`, Datastore `28081`, Coordinator `28091`, Gateway `28090`, and UI `25173`. The final dist hashes are recorded beside the pre-run hashes.

The sanitized per-process environment record shows `PROCESS_COUNT=8`, `DELIVERY_SHARD_COUNT=8`, the shared task Datastore project, and Delivery endpoint. Container identities, image digests, port bindings, and cleanup status are recorded in `containers-inspect.json` and the adjacent container snapshots.

The concurrent public Node-client burst passed: 32/32 generated Message posts had public outcome `ok`, all 32 expected Message IDs appeared in the BoardMessageView query, and none were duplicated or missing. The bounded run completed in about 1.2 seconds after eight projection reads. The API exposes no Command/Ack ID in the public post outcome, so this evidence does not claim a Command-ID join or handler-entry count. See `burst-attempt2/result.json` and its raw output log.

The real React UI acceptance passed in two independent browser contexts. Each context posted one unique Message, both existing pages observed both projected rows without reload, both live statuses remained connected, and Playwright recorded no console errors or failed requests. Browser screenshots and `browser/result.json` are retained under `browser/`.
