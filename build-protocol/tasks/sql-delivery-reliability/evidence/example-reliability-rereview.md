# Example reliability rereview

Scope: only the accepted Message Board launcher, burst-helper, and custom local UI-origin corrections. Existing performance/reliability reviewer profile was explicitly dispatched as `gpt-6-sol` / `medium`; runtime self-introspection is unavailable. This is a source and recorded-evidence review. I did not run builds, tests, services, or alter live resources.

## Disposition

- **P1 burst timeout: resolved.** `evidence/message-board-burst.mjs:41-65` establishes a 45-second absolute deadline and abort controller. All concurrent `post` calls receive that signal (lines 72-95), each query and polling delay is bounded by the remaining deadline (lines 133-157), and client close has a separate three-second bound (lines 173-180). Each Message ID retains its public outcome, including pending or thrown calls, in `postOutcomes`; the final JSON is written on failure and cleanup errors remain visible. This does not claim a Command/Ack ID or handler-entry count, which the public outcome does not expose.
- **P2 duplicate projection accounting: resolved.** `message-board-burst.mjs:125-160` filters to the expected run-specific Message IDs, counts occurrences per ID, fails on any duplicate, and records the actual observed IDs, missing IDs, duplicate IDs, and row count. `projected` now comes from observed rows rather than the requested count.
- **P2 launcher descendant cleanup: resolved for the changed listeners.** Both launchers start the compiled app and Vite as direct `node` children (`examples/message-board/scripts/start-local-single-process.sh:34-43`, `start-local-multi-process.sh:94-121`). Their recorded PIDs are the listeners and cleanup sends TERM, waits up to about five seconds, sends KILL if needed, and reaps them (`single:17-29`, `multi:43-57`). The focused SIGTERM controls bind the app/UI ports after the single launcher exits and the app/Gateway/UI fixture ports after the multi launcher exits (`examples/message-board/scripts/launchers.test.mjs:29-114,209-319`). The recorded six launcher tests passed. The multi test uses direct-child listener fixtures; it does not independently prove graceful shutdown of real managed replicas, which is outside this narrow correction.
- **Custom UI origin: resolved.** `examples/message-board/app/src/local-application-server.ts:23-30` validates `MESSAGE_BOARD_WEB_PORT` and passes its loopback origin to `run({ webOrigin })`; the single launcher passes the same selected port at line 34. The recorded compiled HTTP OPTIONS control was red with 403 before this change and green afterward, and the focused app/Projects checks passed 9/9.

No remaining confirmed finding in this rereview scope. Live 32-post and browser acceptance were still pending in the cited progress record; their results must be evaluated separately when available.
