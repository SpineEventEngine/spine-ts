## Confirmed findings

1. **P2 — An Inbox read failure can satisfy the volatile-loss absence proof.** `packages/server-blackbox-tests/test-fixtures/project-worker.mjs:269-304` turns each failed shard read into `{ shard, error }`. `packages/server-blackbox-tests/test-fixtures/project-process-faults.mjs:1030-1036` then maps absent `rows` to `[]` and asserts no old message. If a restarted Delivery Inbox read fails, that absence assertion passes even though the test has not observed the Inbox. The earlier pending-row check requires a row, but the post-restart check does not. Minimal fix: assert that every fresh shard observation has no `error` and is not `truncated` before testing absence; retain the existing bounded row scan.

2. **P2 — The wrapper's watchdog does not bound reaping after escalation.** `packages/server-blackbox-tests/test/project-process-faults.integration.test.ts:66-84` sends `SIGTERM`, then `SIGKILL`, but the sole awaited promise resolves only on child `exit` and has no post-escalation deadline. If the child remains unreaped, this wrapper never reaches its resource/cleanup diagnostics; the Vitest timeout becomes the only outer bound. The neighboring matrix wrapper has an explicit bounded reap race. Minimal fix: add a finite post-escalation reap timeout and surface the durable resource/cleanup state on that path, preserving the existing process-group termination.
