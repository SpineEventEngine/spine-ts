# Subscription lifecycle scoped coverage

The frozen 11-suite V8 run passed 632/632 tests (`subscription-scoped-coverage-final-review.log`). The changed-production intersection in `subscription-changed-coverage-final-review.txt` is 269/280 executable lines and 171/196 branch arms. Workspace-wide 90% thresholds were disabled only for this scoped diagnostic; the final release gate remains open.

All changed production lines and branch arms are exercised in the native adapter, NodeCoordinator, and SpineServices. The new HTTP/2 NodeCoordinator test rejects a mismatched child ID before logical readiness. The generic kernel tests cover all-child ACK, invalid and duplicate child ACK, pre-ACK cancellation, transformed ACK failure, sink failure, and cleanup retry. Authenticated Cancel tests distinguish the same context from a foreign actor while one cleanup is pending.

Remaining unhit arms have these control-flow dispositions:

- `auth/subscriptions/index.ts:1160` checks whether the cancellation entry map was removed before an entry's settlement callback. The normal path retains the map until that callback removes its entry; the concurrent foreign-context test covers the other entry still present. This arm protects an unexpected external/lifecycle removal, not ordinary Cancel coalescing.
- `client-web/client.ts:1015,1076,1131,1134,1327,1502` guard cancellation or generation changes between settled promise continuations, an accepted wire losing the topic already validated in `#subscribeWire`, and an obsolete cleanup callback after a newer cleanup replaces it. The selected tests cover active Cancel/retry, EOF and malformed ACK, late reauthentication, and iterator/close overlap, but not every microtask race or impossible accepted-wire shape.
- `client-web/client.ts:1103,1321,1353` are reachable unusual failures: terminal Subscribe before a wire exists, a caller retry policy returning a non-positive/unsafe delay, and a non-Error recovery rejection. The test set does not separately inject these three; they remain explicit review/final-gate gaps rather than a claim that all client failure branches are covered.
- `deployment/backend-membership-kernel.ts:464,555,577,745-747,890,960,986,997,1031,1051,1082` guard old activation/child completions, failure or cancellation before readiness, membership removal while a relay is active, simultaneous cleanup on one client, a late update after cancellation, ACK settlement after cancellation, and non-Error child failures. The selected tests exercise the ordinary ACK and cleanup boundaries and several races, but do not force every interleaving in this list. `:987` is the optional ACK predicate's absent arm; `#newReadiness()` only creates the state when that predicate exists. `:982-984` are unreachable from the current call site because `#activateChild` calls `#relayChild` only with defined readiness; the generic path passes its sink directly. `:1017-1019` cannot arise after every required child is seen unless retained internal state is mutated outside its invariants: the first ACK sets `readiness.first`, and activation sets `state.updates` before child starts.

These are scoped-test dispositions, not release-wide coverage or real-process matrix acceptance. No source suppression or artificial branch-only test was added.
