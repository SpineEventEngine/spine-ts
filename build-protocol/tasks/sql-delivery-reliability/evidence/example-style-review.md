## Findings

1. **P2 — The two-task projection regression does not establish that both task Events reached the project-keyed row.** `examples/projects/test/topology.test.ts:132-149` posts both tasks before its first TaskList read and then checks only the second task's name. That assertion would also pass if the first TaskCreated Event were never routed or projected; the absent task-ID row assertion only checks the key used by the second Event. This matters because the correction specifically claims that two task Events advance the same project-keyed TaskList row. Read and assert the first task's value at the project key before posting the second, then assert that the same row advances after the second. The earlier weighted-project test checks one different task and does not close this gap.

2. **P3 — The port-zero shutdown test can fail on a valid OS-selected port and leave its child running.** `examples/message-board/app/test/local-application-server.test.ts:80-83` asserts `port !== 8090` even though `MESSAGE_BOARD_LOCAL_PORT=0` permits the OS to choose any available port, including 8090. On that rare choice, the assertion throws before `stop()` and the spawned server survives the test. Assert a valid nonzero selected port and put child termination in `finally` so a failed assertion cannot leak the process; the release-of-port check can still use the selected port.

The launcher port/image-tag validation, Compose variable alignment, ACK-versus-update separation, and both acceptance harnesses show no other concrete style or maintainability finding within this scope. The active live/browser run may add execution evidence; this review makes no live acceptance claim.
