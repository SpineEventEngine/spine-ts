## Confirmed findings

1. **P2 — Verify the death boundary before accepting crash evidence.** In `packages/server-blackbox-tests/test-fixtures/project-process-faults.mjs:401-402`, `:503-506`, `:812-817`, and `:1005-1010`, `kill("SIGKILL")` return values are ignored, and several `waitExit(..., 2_000)` results are ignored. `waitExit` explicitly returns `undefined` on timeout (`:1084-1097`). The first, partial-publication, and volatile-loss cases can proceed to restart with an old worker or Delivery process still alive; the after-save case verifies the selected Planning worker but not the surviving workers. In the first case the handler gate can also expire between the pre-kill state read (`:398`) and the signal, so that read alone does not prove death before effect. Require a successful signal and observed `SIGKILL` exit for every targeted PID before restart, and recheck absence of the Planning effect after the selected worker exits. Fail the scenario if either boundary is not established. Keep each child in cleanup tracking until its exit is confirmed.

2. **P2 — Fail volatile-loss proof when post-restart Inbox inspection is incomplete.** `packages/server-blackbox-tests/test-fixtures/project-worker.mjs:275-303` converts a shard read failure into `{ shard, error }`. In `project-process-faults.mjs:1030-1036`, the final assertion flattens available `rows` and accepts an empty list even if every shard read failed or was truncated at the 1,000-row limit. The pre-crash `:975-985` check likewise allows errors in other shards. Require every expected shard to have no `error` and `truncated !== true` before asserting that the exact pending message is absent. A focused injected-read-failure behavior test would protect this false-positive path.
