## Finding

**P2 — Reject a second original-Event recipient row when classifying a repeat.** `classifyCrashReplay()` at `packages/server-blackbox-tests/test-fixtures/project-process-fault-observations.mjs:62-93` filters to `status === "TO_DELIVER"` before checking that one row exists in each snapshot. The matrix audit repeats the same filter at `build-protocol/tasks/sql-delivery-reliability/evidence/process-fault-matrix/run-process-fault-matrix.mjs:366-375`. If a `DELIVERED` row D and pending row P share the original Event, delivery target, and typed recipient, the code sees only P and accepts one old/fresh handler pair. The old entry could have processed D, so the evidence would not link **both** entries to the same pending row P. The focused negative table does not include this D+P case. Select all rows for that original Event and exact typed target in each complete snapshot, require exactly one matching row, then require it to be the same `TO_DELIVER` message before and after kill; add a negative case with D+P. Apply the same rule in the matrix audit so its independent validation cannot accept a duplicate that the driver should reject.
