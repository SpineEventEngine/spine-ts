## Shared fixture boundary

The package-local Project fixture is the domain-correct base: `CreateProject`
is posted through CommandService; `ProjectCreated` is routed to distinct
Planning, Staffing, Portfolio, and Projection recipients; handler entry records
include PID and are synchronously appended. The current worker IPC in
`project-worker.mjs` is limited to `start`, `post`, `inspect`, and `close`.
`inspect` supplies state and Event ID/envelope hashes, but those alone cannot
prove handler counts or absence of Command replay. Extend only the test fixture
control channel/logging for gates, repair, selected failures, and attempt
evidence; production APIs already provide exact-ID repair and direct Delivery
monitor configuration, while the full runtime Delivery assembly currently
does not expose monitor injection.

The existing four-server task database configuration and MySQL/PostgreSQL
admin-trigger examples are the source for SQL setup. Do not count mocked tests,
successful reposts, or final state alone as proof of trigger boundaries,
at-least-once counts, SQL query cost, or transport lifecycle. These mapped
extensions are requirements, not claims that the live cases have run.
