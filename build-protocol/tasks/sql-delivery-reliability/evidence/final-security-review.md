## FS-01 — Resolved: API guide claimed a built-in subscription quota that is absent

- Priority: P2 documentation/trust-boundary correction. The availability exposure is real, but it predates this task and the removal of arbitrary global capacity coordination was explicitly required in T-0137. It is not a request to restore that scheme.
- Prerequisite and impact: a caller admitted to `SubscriptionService.Subscribe` can create many distinct pending definitions, then activate them. Active definitions have no framework TTL. Retained rows increase database storage and make each ten-second reconciliation load a complete snapshot and attach observers. The application/ingress must decide who may subscribe and how much retained work to allow.
- Evidence: `docs/api/README.md:533-538` says the built-in registry admits 1–100 definitions. `packages/server/src/context/bounded-context.ts:2351-2362` constructs `StorageSubscriptionRegistry` directly. Its `create()` at `packages/server/src/stand/subscription-registry.ts:461-491` reads and conditionally writes by ID with no aggregate admission count; `snapshot()` at `:559-563` loads all definitions. `packages/server/src/stand/subscription-runtime.ts:99-160` reconciles that full snapshot every ten seconds and attaches active entries. `packages/server/src/services/spine-services.ts:475-509` creates a fresh UUID per successful Subscribe. `SpineServices.subscriptionLimit` is correctly documented in its TSDoc at `:853-863` as a limit on concurrent unknown-ID cancellation work only, and checked only at `:687-694`.
- Baseline and policy: `git show 658da1cdddcb8fd40f9205b1c200abc3a58dd62e:packages/server/src/services/spine-services.ts` has the same narrow `subscriptionLimit` use; this is not a task regression. `build-protocol/tasks/T-0137-stand-subscriptions/TASK.md:24-29` expressly deletes arbitrary global capacity coordination, and `build-protocol/tasks/T-0213-deployment-correction-closure/WORKLOG.md:80` excludes later retained-subscription capacity work. The current guide's quota sentence is therefore stale.
- Correction and focused security disposition: `docs/api/README.md:532-539` now states that the built-in registry has no global retained-definition quota, active definitions have no framework TTL, and application or ingress admission must bound acceptable use. It separately preserves `subscriptionLimit` as the unknown-ID cancellation concurrency limit and `queueLimit` as the per-stream update bound. This matches the source and the T-0137 policy; FS-01 is resolved without runtime changes or a new quota contract. `evidence/final-security-doc-correction.md` records passing formatting, diff, and stale-claim checks. This focused re-review did not reopen unrelated security boundaries.
