## Findings

1. **P1 — Forced child cleanup can become a successful retry.** `packages/server/src/server/managed-server-application.ts:2040-2055` treats a missing drain acknowledgement as a failed close and sends TERM/KILL. When that process exits, `#onExit` removes it from `slot.replica` at lines 1064-1075. The first `close()` rejection clears the retry promise at lines 1155-1164 while leaving `#shutdownFailure` unset. A second call rebuilds its child list from current slots at lines 1276-1283, finds no failed incarnation, and can resolve after Coordinator cleanup. The same loss occurs when a child reports `close-failed` and exits before retry. Thus a forced shutdown is relabeled graceful by a later call, contrary to D-0131's terminal force/failure invariant. Retain the failed incarnation/result through retry and make a subsequent close report the forced failure while still allowing remaining cleanup. Add a regression with a real or controlled child that misses acknowledgement, exits after TERM, then receives a second `close()` before the managed deadline; assert both calls reject and the parent listener still closes. Existing missing-ACK tests cover only the first result or deliberately permit success after an exited failed child.

2. **P2 — Deadline force path leaves both membership kernels unclosed when reconciliation hangs.** `packages/server/src/server/node-coordinator.ts:447-449` waits for `#membershipReconciliation` before closing the subscription kernel. The normal `#closeOnce` also waits for that promise before closing either kernel at lines 674-685. If reconciliation never settles, the parent deadline invokes `forceNetworkClose()` at lines 421-429, which destroys network handles and stops member callbacks but never starts either kernel's `close()`. The managed force path at `packages/server/src/server/managed-server-application.ts:1233-1259` does not invoke another Coordinator cleanup path. Consequently the framework's kernel abort/controllers, retained relays, and native clients are not even asked to close on this exact timeout path. Start independent best-effort kernel close/abort work in the force path without waiting for reconciliation, observe any late rejection, and retain the original timeout result. A focused stalled-reconciliation test should show both kernel cleanup attempts begin while the network and child force operations finish within the shared bound. This finding does not claim arbitrary custom client resources can be fully reclaimed.

No other confirmed reliability defect was found in the changed execution paths. The first-close deadline, child silent-parent watchdog, two-phase drain/relay ordering, retry coalescing, and normal HTTP/2 session close follow the stated contract on the inspected paths. The missing stalled-reconciliation and forced-retry behaviors above are the material behavior-test gaps.
