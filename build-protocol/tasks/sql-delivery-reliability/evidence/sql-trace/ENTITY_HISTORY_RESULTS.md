# Entity and history SQL results

Entity saving, standalone history append/read and bounded history maintenance pass on PostgreSQL 16.15/18.6, MySQL 8.4.10 and MariaDB 11.4.13 (12 captures). Exact metadata, initialization blocks and independent data statements are in `storage-sql-classification.json`; `classify-storage.py` reproduces classification. Domain fixtures use generated Task state, TaskId/TaskListId, and TaskCreated Events. Explicit builder table names contain a fresh random run identifier, so truncation affects only that fixture's tables.

Each measured Entity save emits four INSERT/upsert statements in the required order: state history, diagnostic history, delivery Event, current state. The measured data sequence also includes one ordinary SELECT. All data writes occur outside explicit transaction or lock wrappers. PostgreSQL repeats four schema-initialization transactions through fresh record handles; MySQL and MariaDB perform twenty setup statements. These schema checks are distinct from data persistence.

Standalone history append/read emits five data statements with no initialization or transaction/lock wrappers in the prepared-handle interval. The case checks backward histories and state-at-time. Maintenance emits nine data statements on PostgreSQL and eight on MySQL/MariaDB, without explicit transactions or locks. It trims history, truncates states and diagnostics, verifies empty histories, and confirms the current record remains present.

The first MySQL Entity assertion compared Buffer and Uint8Array prototypes. It was corrected to compare complete serialized EntityRecord bytes; no framework change was made for this fixture issue. Capture extraction initially used a UTF-8 CAST that returned null for binary-bearing MySQL statements. Those incomplete logs remain, but acceptance uses fresh successful captures produced by the corrected HEX-plus-Latin-1 extractor. The classifier rejects absent statements rather than treating them as evidence. All successful and failed captures report restored logging.

This is SQL-shape and resulting-state evidence. Separate behavior tests establish partial-prefix failures and retry boundaries. These captures do not establish the remaining delivery/publication lifecycle, process matrix or shutdown guarantees.
