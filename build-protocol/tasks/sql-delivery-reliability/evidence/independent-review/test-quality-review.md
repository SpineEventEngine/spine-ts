## Confirmed findings

1. **P2 — The new delivery wire round trip can pass with two mutually wrong conversions.** `packages/delivery-client/test/codec-immutability.test.ts:245-249` encodes each label/status and immediately decodes with the same codec, then asserts only the original strings. `DeliveryMessageCodec.label/status` and `decodeLabel/decodeStatus` are independent mappings in `packages/delivery-client/src/wire/codec.ts:559-642`. If both mappings swap, for example, `SCHEDULED` and `DELIVERED`, every case in this test still passes while a real delivery server interprets the written status incorrectly. Assert each encoded `InboxMessageSchema` label/status against its generated enum, and independently decode wire fixtures made with those enums. Keep the domain-correct Command/Event fixtures.

2. **P2 — The distributed Compose test does not prove the claimed service configuration.** The new test at `examples/distributed-message-board/test/topology.test.mjs:48-59` searches raw YAML for three image tags, a port binding, and `BROWSER_ORIGIN` anywhere in the file. It passes if those strings are comments, duplicate/unused keys, or assigned to the wrong service, while the effective Gateway can use a different browser origin or image. Parse the Compose document and assert the resolved `services.delivery.image`, both application images, `services.gateway.image`, Gateway port mapping, and Gateway environment field by path; preferably also validate the interpolated configuration with `docker compose config` in a focused topology check. The related `examples/message-board/deploy/compose/topology.test.mjs:26-30,60-72` additions have the same raw-text weakness for image tag and public port fields despite that file already parsing Envoy YAML.

3. **P2 — The malformed-response check passes if the response budget check is removed.** `packages/delivery-client/test/codec-immutability.test.ts:294-304` calls `DeliveryRequestCodec.responseBytes` directly with an impossible `Symbol` payload cast through `never` and asserts only that it does not throw. An empty `responseBytes` method passes this new test, so it gives no evidence that a remote response is bounded or that the public client reports malformed data correctly. Replace or supplement it with a valid response just below and above the 4 MiB limit through the public client/codec, and assert the oversized response is rejected as `DeliveryProtocolError`. Test malformed peer data through the public decode path with a concrete protocol outcome if that behavior is required.
