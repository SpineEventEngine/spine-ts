## Findings

1. **P2 — The MyISAM “current-only” case runs the same full-history mutation.** `packages/storage-mysql/test/mysql-integration.test.ts:541-567` constructs a single `entityInput(context)` and calls `mutation(context, input, ...)` for both `with-history` and `current-only`. `entityInput` defaults both history flags to `true` at line 815, and `mutation` always supplies `states`, `diagnostics`, and `events` at lines 883-899. Thus the test can pass while the MyISAM path for disabled optional histories or a current-state-only commit is broken. The two successful Promise resolutions also do not read back the rows. Add a separate Entity input with disabled histories, use a mutation appropriate to that contract, and read current state plus the absence/presence of each relevant history and Event family after both commits.

2. **P2 — Concurrent Entity commit tests accept lost or inconsistent persisted outcomes.** The PostgreSQL case `packages/storage-postgres/test/postgresql-integration.test.ts:475-497` asserts only that both promises resolve. The MySQL case `packages/storage-mysql/test/mysql-integration.test.ts:714-732` adds only `toBeDefined()` for the final current row. A provider could return success for both calls while writing one stale value, mixing state and diagnostic histories, or failing to persist one commit; these tests would still pass. Read the final Entity state and immutable histories through a fresh handle and compare their versions and payloads to one allowed serial ordering. For the MySQL fixture, compare the final current payload with the selected winner and assert the expected history/Event rows; for PostgreSQL, assert an actual persisted state and the contract's allowed final version/order. If the contract promises only last-writer-wins, state that expectation and check the final payload belongs to a successful commit.

3. **P2 — The live MySQL CAS race checks return flags but never checks the stored winner.** `packages/storage-mysql/test/mysql-integration.test.ts:615-640` requires exactly one `true` for present and absent IDs, but never reads either record afterward. A compare-and-set implementation that reports a single winner while leaving the prior bytes or inserting the loser's value would pass. Read both IDs after each race and compare the persisted value to the contender whose call returned `true`; check that the losing contender's value was not stored. This is especially useful here because the test deliberately changes the underlying bytes before the present-record race (lines 610-614).

## Coverage inventory and limits

The process fault driver checks actual injected insert/ack attempts, saved Event identity, recipient rows, restart and repair against the original Event ID. Controlled gates, SQL triggers and protocol proxies are legitimate phase controls; they were not classified as artificial merely because they inject faults.

This review did not inspect every unchanged helper or run database/process tests. It did not infer a universal discovery, exactly-once, shared Inbox durability, ten-second deadline, or legacy behavior guarantee. No production files or tests were edited.
