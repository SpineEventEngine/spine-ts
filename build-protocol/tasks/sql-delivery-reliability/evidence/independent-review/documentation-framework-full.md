## Findings

**P2 — The browser extension guide says subscription readiness follows an active wire, but readiness requires a successful matching ACK.** Its lifecycle diagram transitions `connecting --> connected: wire active` ([`docs/BROWSER_CLIENT_AUTH_EXTENSION_GUIDE.md:84`](../../../../../docs/BROWSER_CLIENT_AUTH_EXTENSION_GUIDE.md)). The client only reports `connected` after receiving a matching response-only successful ACK; an idle subscription can become ready without a business update, while malformed, mismatched, failed, or missing ACKs do not establish readiness ([`packages/client-web/REFERENCE.md:26`](../../../../../packages/client-web/REFERENCE.md), [`docs/api/README.md:146`](../../../../../docs/api/README.md)). Replace the transition label with the matching successful ACK and note that no business update is needed.

**P2 — Public `DeliverySupervisor.close()` timing and its non-total bound are not documented.** The API index exposes `DeliverySupervisor` and explains context and managed-server shutdown budgets, but does not describe direct `close({ graceMs })` ([`docs/api/README.md:58`](../../../../../docs/api/README.md), [`docs/api/README.md:72`](../../../../../docs/api/README.md)). Its public option defaults to 30,000 ms and applies separately to active-work grace and release cleanup ([`delivery-supervisor.ts:402`](../../../../../packages/server/src/delivery/delivery-supervisor.ts), [`delivery-supervisor.ts:801`](../../../../../packages/server/src/delivery/delivery-supervisor.ts)). After these waits, close still awaits active work that remains in flight ([`delivery-supervisor.ts:425`](../../../../../packages/server/src/delivery/delivery-supervisor.ts)); an already-entered callback or storage effect that never settles can keep direct close pending beyond both grace periods. Document the per-phase grace and that it is not a hard total close deadline.

The previous Inbox cleanup atomicity finding is closed by the current correction: `packages/server/REFERENCE.md` now says eligibility is checked and deletion is by ID without a stored-row snapshot comparison or a second shard-session check ([`packages/server/REFERENCE.md:869`](../../../../../packages/server/REFERENCE.md)).

No additional concrete contradiction was found in the remaining framework files in this bounded pass. In particular, the paging descriptions state the exact continuation tuple and distinguish live paging from a cross-page snapshot; shutdown descriptions distinguish context, managed-server, and direct-supervisor paths; and the user/spec/architecture descriptions of independent Entity writes, immutable retry inputs, saved-Event repair limits, acknowledgement versus processing failure, and volatile in-memory Delivery were consistent with the focused source checks.
