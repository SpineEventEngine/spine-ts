## Confirmed findings

1. **P1 — ACK-disabled failures bypass the new logical cleanup contract.** `packages/deployment/src/internal/backend-membership-kernel.ts:460-463` routes the lifetime rejection into `#failActivation`, but `:597` calls `cancel()` only when `readiness !== undefined`. With `isActivationAck` omitted, a required child's post-update rejection or EOF now rejects the public `activate()` promise while leaving the retained definition and child entries in `#definitions`. `#failChildActivation` aborts streams but does not dispose the child handles or clear the definition. This violates D-0133's requirement that a failed generic logical activation dispose its admitted children through bounded cleanup, and means cleanup failures cannot be included in the activation result. The new generic test at `membership-kernel.test.ts:~877` asserts only the original rejection and then calls `close()`, so it does not establish the promised activation cleanup. Make failure cleanup independent of ACK validation, and assert disposal/definition removal and retained cleanup failure behavior for an ACK-disabled activation.

2. **P2 — affected SPI TSDoc still promises cancellation-only completion.** `packages/deployment/src/internal/backend-membership-kernel.ts:425-430` is re-exported from `packages/deployment/src/spi/backend-membership.ts`; its `activate()` now rejects on an unexpected current child rejection or EOF after readiness, but `@returns` still says completion is after cancellation. The downstream package-internal `DynamicUnaryForwarder.activateDefinition()` at `packages/auth/src/gateway/dynamic-unary-forwarder.ts:268-273` repeats that claim while returning the kernel promise directly. State that cancellation completes normally and an unexpected current child failure terminates with its cause, with cleanup failure potentially aggregated. This is a narrow affected contract clarification, not broad documentation work.
