For missed-notification and release-boundary controls, the narrow public seam is `ServerEnvironmentSettings.delivery`: its `ServerEnvironmentDelivery` shape exposes `open`, `close`, `inbox`, `workRegistry`, and optional `source` ([server-environment.ts](/Users/armiol/.codex/worktrees/sql-delivery-reliability/spine-ts/packages/server/src/server/server-environment.ts:52)). A test facade can delegate to a real `RemoteDelivery`, wrap the public `source.observeShardUpdates` to drop one selected observation, and wrap public `workRegistry.release(session, options)` with an IPC/file gate immediately before delegation or immediately after the successful release. `EnvironmentDeliveryWorker` passes those exact ports into the `DeliveryBuilder` ([environment-delivery-worker.ts](/Users/armiol/.codex/worktrees/sql-delivery-reliability/spine-ts/packages/server/src/server/environment-delivery-worker.ts:861)). This avoids a source patch or a new public hook. The existing `handlerGate` in `project-worker.mjs` pauses at handler entry, not after the last empty Inbox read or at work-registry release; it cannot by itself establish either release ordering.

The existing smoke protocol does not currently provide a deterministic SQL race fixture. Its handler gate pauses at handler entry, which is too early, and a second worker submitting a `CreateProject` Command may itself consume the resulting Inbox row before the gated worker resumes. That does not establish which process recovered a deliberately missed notification. The public `ServerEnvironmentDelivery` shape can supply test-only `inbox`, `workRegistry`, and `source` ports to the real environment delivery worker; its source is validated structurally and `createSupervisorGroup()` forwards those ports to `DeliveryBuilder` ([validation](/Users/armiol/.codex/worktrees/sql-delivery-reliability/spine-ts/packages/server/src/server/server-environment.ts:522), [port forwarding](/Users/armiol/.codex/worktrees/sql-delivery-reliability/spine-ts/packages/server/src/server/environment-delivery-worker.ts:852)). A purpose-built fixture can therefore delegate to SQL Inbox and registry ports while controlling source observations and release. It must use the exact descriptor storage context (including tenant scope); the current process-smoke fixture does not expose a release gate or a way to coordinate a missed observation with a persisted row. `Inbox`/`InboxStorage` and `InboxMessageInput` are public ([exports](/Users/armiol/.codex/worktrees/sql-delivery-reliability/spine-ts/packages/server/src/index.ts:120)); direct low-level injection is possible through `Inbox.receive(input)` or `InboxStorage.write(message)`, but a hand-built row still needs a domain-correct packed Project target ID, `REACT_UPON_EVENT` label, generated Event payload, exact shard, and valid ordered metadata. Prefer the delegated real repository/EventStore ingress if the fixture can gate after persistence and before its notification; source inspection here did not establish that ordering as an existing test seam.

For the before-release and after-release samples, use one Project app process and one selected shard, and have the test source withhold the chosen observation while a release gate records the exact transition. Persist one typed Project Event Inbox row, confirm it by exact ID through `inspectDelivery`, then emit the deliberately withheld observation at the chosen side of release; count handler entries by Inbox ID and verify the saved Event and pending/delivered row in SQL. Keep a normally observed control row to prove the route is live. The harness needs new test-only IPC gates for “row persisted,” “source observation released,” and “work-registry release delegated/returned”; these coordinate the row and notification without using another app worker as an uncontrolled competing consumer. Do not count SQL reads or successful process-level handler totals alone as proof of the intended worker recovered the row.

## Timer choices and limits

`DeliverySupervisor` is public and accepts `recoveryMs` and `staleMs` ([options](/Users/armiol/.codex/worktrees/sql-delivery-reliability/spine-ts/packages/server/src/delivery/delivery-supervisor.ts:748)); `DeliveryBuilder` is public and accepts a real storage factory, Inbox and work registry ([builder](/Users/armiol/.codex/worktrees/sql-delivery-reliability/spine-ts/packages/server/src/delivery/delivery-builder.ts:239)). That permits a component-level SQL fixture to test both omitted recovery interval and an explicit short override against a deliberately missed source observation. It will test the public supervisor/delivery components, but it will not execute `EnvironmentDeliveryWorker`’s private Project handler routing.

There is no public `ServerEnvironmentSettings` or `ServerOptions` field for the environment-created supervisor’s `recoveryMs`; `RuntimeDeliverySupervisorGroup` passes only `source`, `delivery`, and `onMessage` ([construction](/Users/armiol/.codex/worktrees/sql-delivery-reliability/spine-ts/packages/server/src/server/environment-delivery-worker.ts:541)). Wrapping the public delivery ports can gate release and notifications, but cannot set an interval override for the full Project server path. If acceptance requires the explicit override with the actual framework route, that deterministic case needs a production configuration contract or an internal-only fixture; neither is present in the current public assembly. Do not represent the direct component test as full-app override coverage.

The separate defaults can be checked without changing those APIs: omitted `staleMs` is exercised independently by the existing fake-timer supervisor test ([delivery-supervisor.test.ts](/Users/armiol/.codex/worktrees/sql-delivery-reliability/spine-ts/packages/server/test/delivery/delivery-supervisor.test.ts:64)); `DeliveryServer` can be started with `{ port: 0 }` and no processing-timeout option, whose resolver default is `0` ([config.ts](/Users/armiol/.codex/worktrees/sql-delivery-reliability/spine-ts/packages/delivery-server/src/server/config.ts:111)). Sanitize `SHARD_PROCESSING_TIMEOUT` from the child environment when asserting the server default, since that variable also configures it. These existing unit tests establish configuration behavior only, not the live SQL timer cases.

## Idle SQL capture

Use the existing [SQL trace capture wrapper](/Users/armiol/.codex/worktrees/sql-delivery-reliability/spine-ts/build-protocol/tasks/sql-delivery-reliability/evidence/sql-trace/capture.mjs:16) around an opt-in process fixture. Start 2, then 8 database-only Project workers, finish a small warmup workload, emit a unique SQL marker, leave all workers alive and idle for multiple recovery intervals, and classify statements after that marker. The wrapper already selects one task engine, bounds the command, captures/restores provider logging, and writes paired raw-log/metadata files ([SQL_TRACE_PLAN.md](/Users/armiol/.codex/worktrees/sql-delivery-reliability/spine-ts/build-protocol/tasks/sql-delivery-reliability/SQL_TRACE_PLAN.md:48)). Keep the timer sample separate from startup and warmup SQL.

One harness incompatibility needs a deliberate choice before implementation: `project-process-smoke.mjs` creates a per-run UUID database, but `capture.mjs` configures PostgreSQL logging for the fixed database names in `evidence/databases.json` and filters MySQL-family connections to those same database names. A trace of the current smoke child therefore will not automatically cover its UUID database. Either add bounded trace selection for the child’s database before its connections start, or use a pre-provisioned trace database with isolated names and a verified cleanup strategy. Do not claim idle-SQL evidence until the selected database is demonstrably included in the capture.

## Smallest follow-up fixture work

Extend the existing smoke worker protocol with (1) an optional idle hold after accepted work has converged, (2) a test-only `ServerEnvironmentDelivery` facade around SQL Inbox/work-registry ports and a controlled source, (3) IPC gates for persisted-row/source-observation/release boundaries, and (4) durable release/arrival/handler timestamp records keyed by Inbox ID. Add a direct `DeliverySupervisor` SQL component case for the explicit `recoveryMs` override, labeled separately from full-app coverage. For idle SQL, resolve the UUID-database trace mismatch first. No current public collaborator lets a full-app test set an explicit recovery interval, and the existing handler-entry gate does not locate the release race precisely. The public Inbox port methods are `receive(input)`, `read(shard, options)`, `readMessage(id)`, and `markDelivered(message)`; custom ports must also implement exact duplicate removal, while `removeDelivered` is optional ([DeliveryInbox](/Users/armiol/.codex/worktrees/sql-delivery-reliability/spine-ts/packages/server/src/delivery/delivery-ports.ts:46)).
