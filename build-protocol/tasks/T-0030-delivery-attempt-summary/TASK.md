## Objective

Add a package-internal exact-message summary/read path over the retained
delivery attempts created by T-0029, so later retry monitors can make bounded
per-message decisions without scanning all retained attempts.

## Scope

- Add an internal exact-message summary/read path to
  `packages/server/src/delivery/delivery-attempts.ts`.
- Read only the bounded 100 retained slots for one inbox message identity.
- Return deterministic sanitized facts useful to later retry policy:
  - ordered retained attempts for the message;
  - retained attempt count;
  - latest attempt, when present;
  - latest failure stage/reason, when present;
  - latest accepted flag, when present.
- Preserve existing broad `DeliveryAttempts.read()` behavior.
- Preserve T-0029 retained-attempt storage format, type URL, sanitization,
  identity validation, safe-integer validation, and fail-closed corruption
  behavior.
- Update docs to describe the internal summary as retry-policy preparation
  while keeping retry monitors/workers deferred.

## Out Of Scope

- Public `DeliveryMonitor`, `FailedReception`, repeat-dispatch,
  mark-delivered, retry/backoff, timer, scheduler, or cancellation APIs.
- Immediate retry, policy decisions, or changing `Delivery.drain()`,
  `DeliveryLoop`, or `DeliveryWorker` behavior.
- Production worker/process supervision.
- ZeroMQ topology, broker lifecycle, remote/multi-host transport, or health
  policy.
- Durable catch-up storage, projection catch-up through inbox storage, or

- New `IMPORT_EVENT` support.
- Public end-user delivery APIs.
- Production storage adapters, query planners, or broad storage capability
  negotiation.
- Raw payload/error retention, stack traces, or unbounded exception text.

## Acceptance Checks

- Exact-message summary reads only the bounded per-message attempt slots, not a
  broad retained-attempt query.
- Summary returns ordered sanitized attempts for that message and does not
  include attempts for other messages sharing the same shard or inbox.
- Summary returns deterministic `count`, `latest`, latest stage/reason, and
  latest accepted flag values.
- Empty summary for a message with no retained attempts is explicit and stable.
- Corrupt retained attempt records encountered by summary reads fail closed as
  `DeliveryStorageCorruptionError`.
- Summary snapshots do not share mutable `Date`, `ShardIndex`, or nested
  identity objects with internal stored rows.
- No raw `Any.value` payload bytes, raw user errors, stack traces, or unbounded
  exception text are exposed.
- `Delivery.drain()`, `DeliveryLoop`, and `DeliveryWorker` behavior remains
  unchanged; failed rows stay `TO_DELIVER`.
