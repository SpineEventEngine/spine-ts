## Objective

Turn the runtime gaps left after `T-0016i` into an explicit, staged,
implementation-ready roadmap, then select the first non-blocked task and
continue implementation under the autonomous build protocol.

## Trigger

`T-0016i` closed the release-readiness audit, but the codebase and public docs
still intentionally describe deferred runtime pieces:

- process-manager event execution;
- read-side catch-up;
- query and subscription execution over repository routes;
- delivery scheduler/catch-up loops and durable delivery lifecycle;
- durable subscription recovery;
- system-context pairing and broader production server/gRPC lifecycle;
- ZeroMQ endpoint topology and production transport-backed worker execution.

These are not blockers for the verified T-0016 slice, but they must become
explicit tasks before the framework can be called complete.

## Staged Runtime Roadmap

### T-0017a Read-Side Catch-Up

- Goal: replay stored events into projection subscribers and `Stand` without
  re-appending those events.
- Dependency: none; this is the first non-blocked slice after the roadmap.
- Likely files/modules: `packages/server/src/stand/stand.ts`,
  `packages/server/src/bus/event-bus.ts`,
  `packages/server/src/repository/repository.ts`,
  `packages/storage/src/event/event-store.ts`, storage-factory contracts, and
  focused server/storage tests.
- JVM inspection requirement: inspect local JVM docs plus `core-jvm/server`
  `Stand`, projection catch-up, event-store replay, and delivery/catch-up
  sources before design.
- Acceptance criteria: projections can rebuild from stored events through the
  read-side path; replay does not append duplicate events; catch-up stays
  separate from normal live event dispatch; failures are observable and
  retryable within the selected scope.
- Verification: focused catch-up tests, projection/stand regression tests,
  typecheck, format, diff whitespace check, and broader server verification if
  dispatch behavior changes.
- Classification: production parity/runtime completeness; not required for
  minimal local in-memory to-do app readiness.
