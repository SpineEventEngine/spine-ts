## Objective

Add the smallest package-internal retry-decision primitive over
`DeliveryAttemptSummary`, so later delivery monitors or scheduler workers can
make bounded per-message retry decisions without global retained-attempt scans.

## Scope

- Add a package-internal retry decision object under
  `packages/server/src/delivery/`.
- Consume only one `DeliveryAttemptSummary`; do not call
  `DeliveryAttempts.read()` or scan retained attempts globally.
- Support one bounded configurable attempt budget:
  - retryable while retained count is below the configured maximum;
  - exhausted when retained count is at or above the configured maximum.
- Return immutable, sanitized decision facts:
  - decision kind;
  - retained count;
  - configured attempt limit;
  - latest retained failure stage/reason, when present;
  - latest accepted flag, when present.
- Keep decisions observational only.

## Out Of Scope

- Public `DeliveryMonitor`, `FailedReception`, repeat-dispatch,
  mark-delivered, custom monitor actions, or callback APIs.
- Integrating retry decisions into `Delivery.drain()`, `DeliveryLoop`, or
  `DeliveryWorker`.
- Immediate retry, backoff, timers, cancellation, scheduler ownership, worker
  supervision, transport topology, production storage adapters, or production
  environment ownership.
- Any `CATCH_UP` execution semantics.
- New `IMPORT_EVENT` support.
- Raw payload/error retention, stack traces, or unbounded exception text.
- Public end-user delivery APIs.

## Acceptance Criteria

- Decision results are deterministic from one `DeliveryAttemptSummary`.
- Empty summaries are retryable under a positive max-attempt budget.
- Counts below the configured limit are retryable.
- Counts at or above the configured limit are exhausted.
- Invalid max-attempt configuration fails with simple deterministic errors:
  unsafe integers, zero, negative, non-finite values, and unbounded values are
  rejected.
- Decision results snapshot the summary facts they expose and do not share
  mutable retained-attempt objects.
- No raw payload bytes, raw user errors, stack traces, or unbounded text are
  introduced.
- No public package export leaks the retry decision primitive unless a later
  task records a public API decision.
- `Delivery.drain()`, `DeliveryLoop`, and failed-row `TO_DELIVER` behavior
  remain unchanged.
- `CATCH_UP` remains skipped/pending; legacy stored `IMPORT_EVENT` rows remain
  fail-closed.
