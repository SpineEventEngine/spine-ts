# Better Auth native sessions and password login

High-risk native engine integration. The complete TASK ledger, PROPOSAL and
accepted architecture govern this slice. Use exact Better Auth 1.7.16 behavior.

## Contract

BetterAuthIntegration.create exposes sessions, credentials and admitted routes.
SupportedBetterAuthOptions retains native names with the proposal's narrow
allowlist; JavaScript callers receive equivalent construction-time validation.
Reject unsafe secrets/cookies/origins, database overrides, unsupported plugins,
models/hooks/fields, secondary storage and cookie caching. Disable native schema
validation and automatic verification cleanup; the Spine factory prepares data.

Support preprovisioned native password accounts and trusted external verified
login against a complete read-only User directory. A caller-supplied user ID is
not login proof. Map native User to Spine principal explicitly; directory/storage
failure cannot become anonymous success.

RPC resolution invokes native getSession with refresh/cache disabled. An explicit
native renewal route forwards all response cookies and updates only existing
sessions. Replace public native sign-out with strict validated-cookie durable
revocation; stock sign-out cannot bypass failure reporting. Retain expired rows
on normal reads, including the native slow-User-lookup expiry deletion path.

Require outer `routePolicy: BetterAuthRoutePolicy` with application-supplied
`maxRequestBytes` and `timeoutMs`. Apply the same pair to every generated route.
Capture, validate and copy it before the first initialization await; reject
missing, invalid or unsupported fields, including for JavaScript callers. Match
existing BrowserAuthRoute numeric validation without defaults or new bounds.
Preserve immutable structural routes with no auth-to-server dependency.

## Acceptance

Exercise real BrowserServer and native Better Auth engine: correct/incorrect
password, external proof, directory failures, restart, renewal/logout in both
orders, durable logout failure, expiry during User lookup and manual cleanup.
Test exact active-secret rollover behavior; do not infer seamless cookie rollover
from retained secret configuration. Connect local stream invalidation to the
shared authenticated session identity. Update public API/configuration examples.

SupportedBetterAuthOptions uses local structural declarations while preserving
native property names, including hashing and rate-rule callbacks. For a generic
OAuth plugin value, validate and detach supported native options before async
initialization and build the installed native plugin from that configuration.
Do not execute caller-provided plugin implementations. Known native implementation
fields are ignored; unknown features/configuration reject. Test mutation during
startup and an injected init/hook that must never execute.

Derive browser admission metadata from the same validated native configuration,
using the public better-auth/cookies helpers. Include selected native session and
supporting-cookie roles, reject resolved-name collisions, and test default/custom
role names, prefixes and secure-prefix behavior. Disabled cache-shaped cookies
must not authenticate or bypass authoritative reads. No auth-to-server dependency.

With an operation lifetime, native session resolution must return invalidation
covering local logout, captured session expiry and integration close. Release its
monitor/listeners/timer on every exit; no-lifetime reads retain none. This is the
same approved component/native operation contract, not a new distributed signal.

Test required route policy, invalid JavaScript values, captured values from mutable
inputs, mutation during initialization, immutable generated routes and direct
BrowserServer mounting. Exercise configured body boundaries and deadline
cancellation through the real host for login, renewal and strict logout. M11
applies the same policy to OIDC routes and retains its provider cancellation and
late-result tests. Update every integration factory example.

## Selected native related reads

The private factory enables native `advanced.database.joins` and supplies only
Session-to-User `findOne` by token and User-to-Account `findOne` by email. Preserve
the native transformed relation/limit and singular result keys `user`/`account`;
explicit null/empty properties prevent native fallback. Use existing ID/digest
lookups, complete external User validation and the native Account page limit.
Reject other effective joins, predicates and projections before record access.
No public option, index, schema or cross-record transaction is added.

Directory and Account-storage failures must reject without any console or
framework log record, sensitive HTTP output, session creation or anonymous
success. Keep the whole related read under one admitted store operation; pass
its existing signal to external User reads. Recheck expiry/lifetime after each
await, and retain the safeguard against native opportunistic expiry deletion.
Test actual native password/getSession/renewal, stored and external Users,
missing and failed relations, signal/close/logout/expiry interleavings, and
absence of fallback work. M11's joined Account read remains a separate gate.

The effective request matrix is exact for Better Auth 1.7.16. Base predicates
use `eq`, `AND`, sensitive comparison and string values. These calls have no
selection projection; an empty native projection is equivalent to no projection.
Other effective predicates, relation fields, targets or projections reject before
storage/directory work. Syntax discarded by the native factory cannot be
validated later by the custom adapter.

| Native operation  | Base lookup            | Effective joined relation                                                                                 | Raw adapter result                                                                                              |
| ----------------- | ---------------------- | --------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| Session `findOne` | Exactly token equality | `user: { modelKey: "user", on: { from: "userId", to: "id" }, relation: "one-to-one", limit: 1 }`          | Null for no visible Session; otherwise Session fields plus `user: completeUserOrNull`.                          |
| User `findOne`    | Exactly email equality | `account: { modelKey: "account", on: { from: "id", to: "userId" }, relation: "one-to-many", limit: 100 }` | Null for no User; otherwise User fields plus singular `account: completeAccountRows`, including an empty array. |

The Account page size is the pinned native default, not a provisioning quota.
The public options do not expose a default-find-many override. Preserve the
native page and existing stable storage order; do not fetch all Accounts or
special-case credential selection in the adapter.

Password login requires selected Account storage plus either stored User or an
external User source providing both `findById` and `findByEmail`. Validate that
capability before engine startup; missing Account storage or email lookup is a
configuration error. The selected external source replaces the User family.
Verified external login without password checking needs its verifier, complete
User-by-ID source and Session storage, without Account or email lookup.
Test both password source variants and rejection of an incomplete configuration.
