# Better Auth records and controlled provisioning

High-risk optional integration slice. The complete TASK ledger, PROPOSAL section
7 and accepted architecture govern implementation. Historical lab success is
feasibility evidence; production uses the separately verified 1.7.16 pin.

## Contract

Add PersistentBetterAuthStore through auth/better-auth only. Better Auth is an
optional peer; importing the ordinary auth root must not load it. The factory
selects logical models explicitly and creates/checks only selected families by
default. False skips preparation throughout data access. An external users
collaborator replaces the User model; simultaneous stored User is rejected.

Use domain-correct User, Account, Session and Verification Protobuf records with
exact native Date/Timestamp conversion. Adapt real Better Auth operations through
createAdapterFactory to Spine RecordStorage; no native SQL adapter fallback.
Advertise no cross-record transactions. Validate model/field/operator allowlists.

Session token identity and immutable Account provider/subject identity use
canonical unambiguous keys. Conditional create, update-existing and delete use
CAS. Re-evaluate complete predicates after contention; renewal cannot insert.
Bulk affected counts reflect actual successful changes. Verification permits
one immutable value per purpose-qualified identifier in the supported profile.
All supported lookups and cleanup use indexes and finite traversal.

Controlled provisioning requires stopped auth traffic and a single serialized
administrator process. Validate complete records and email/provider-link
uniqueness before exposure. Partial failure prevents listener startup; retry
recognizes identical definitions and rejects conflicts. Do not expose public
signup, account-linking or generic upsert as provisioning.

## Acceptance

Replay real adapter operations through memory, PostgreSQL, MySQL/MariaDB and
Datastore, independent factories and a fresh Node process. Test selected models,
external User absence/outage/completeness, unsupported operations, immutable
keys, predicate-preserving CAS, exact timestamps and explicit cleanup. Keep
expired rows until maintenance; ordinary reads hide them. Optional imports and
declarations must work both with and without Better Auth installed.

The optional public declaration graph uses local structural native option/User
shapes and must not import Better Auth or Bun types. Use the genuine upstream
bun-types1.3.14/sqlite.d.ts only as a development declaration input; full Bun
global declarations are not the supported build environment. Verify actual
workspace/tooling and packed consumer graphs; disposable proof is a prerequisite,
not final package acceptance.
