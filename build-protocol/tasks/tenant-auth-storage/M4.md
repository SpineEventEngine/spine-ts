# Persistent opaque sessions

High-risk authentication and persistence slice. The complete Human-Imposed
Requirements Ledger in TASK.md and PROPOSAL sections 4–6, 8–12 govern this work.
The accepted architecture describes required atomic transitions and cleanup.

## Contract

Add the replaceable OpaqueSessionStore port and PersistentOpaqueSessionStore in
the existing auth package. Use domain-correct Protobuf records: stable random
session ID, credential generation, complete typed principal and exact deadline.
Persistent factories have private constructors, async create/close, default-true
createMissingStructures, M1 non-preparing handles and explicit preparation.
Memory implements the same transitions; do not copy external user directories.

OpaqueSessions uses an async factory and iron-session sealData/unsealData. The
seal contains the reference, generation, scope and exact deadline. Required
application sealing configuration and explicit trusted-clock/lifetime policy
remain visible. The library grace period cannot extend application validity.
Reads do not renew. Rotation creates a seal before atomically replacing the
generation/deadline in the existing record. A failed conditional update never
returns that credential as successful.

## Required behavior

- Concurrent rotations have one winner, including independent storage instances.
- Logout before rotation prevents resurrection. Logout after rotation with an
  older unexpired seal revokes the same stable session. Expired old seals cannot
  resolve or revoke; a fresh independent login is unaffected.
- Storage failures remain failures; no anonymous-success fallback.
- Cancellation checks surround awaited storage operations. Late issuance commits
  trigger observed compensating deletion; no success credential escapes after
  cancellation. Close fences new work and drains admitted work/compensation.
- Selected persistent construction creates/checks by default; false never does.
  Failure closes acquired handles and preserves the injected factory.
- purgeExpired uses caller timing/cutoff, indexed finite traversal and conditional
  deletion. Preserve concurrently extended records; reject partial failure or
  cancellation. No timer, automatic retention default or arbitrary new cap.
- Pin the already verified production library version; preserve actual library
  behavior through expiry/key-rotation tests. Do not hand-write sealing.

## Boundaries

Update maintained component callers and tests directly for the factory API.

implemented by a store test. Keep narrow API/package documentation current.
Run live provider durability/concurrency/cleanup checks before acceptance and
