# Better Auth native OIDC callbacks

High-risk protocol and atomic-consumption slice. The complete TASK ledger,
PROPOSAL native OIDC scenario and accepted architecture govern implementation.
Use the exact pinned native genericOAuth path, separate from component OIDC.

## Contract

Accept only tested redirect-based OIDC configurations with registered providers,
mandatory PKCE and ID-token verification, prelinked accounts and no implicit
signup/linking. Reject unsafe custom hooks/models/remapping and duplicate provider
IDs before listening. Reject `client_secret_basic` and `client_secret_post`
without a nonempty `clientSecret`, and conflicting legacy `authentication` versus
`tokenEndpointAuth` selections. Preserve the public-client `none` path. Test both
missing-secret cases, conflicting selections, and the admitted public path. Preserve native state-cookie validation before atomic
Verification consumption. The losing callback must fail before token exchange;
a missing-cookie attempt must preserve the legitimate transaction.

Native discovery and the integration's trusted metadata read complete during
`BetterAuthIntegration.create()`, before routes are exposed. Creation requires
every configured provider to initialize with matching issuer, client and
signing-algorithm settings; partial initialization and request-time discovery
retry are unsupported. The factory currently has no caller AbortSignal or
bounded startup guarantee. A pending discovery response leaves creation
pending and cannot produce a callback success. `routePolicy.timeoutMs` applies
to admitted routes, not startup.

During admitted callbacks, the integration supplies internal public native
token/profile hooks and a jose JWKS resolver for each callback through the
original generated provider's public ID-token configuration. Trusted endpoint
and JWKS metadata comes from the configured discovery URL at construction;
callers cannot supply custom hooks or replace verification. Keep native state,
PKCE, nonce and ID-token verification mandatory. Token, JWKS, userinfo and User
directory work receives the operation lifetime. Cancelling one callback must
not cancel another callback's network work. A host timeout alone is
insufficient: late session writes require compensation and no cancelled
success may escape. Do not share mutable JWKS resolvers or caches across
callbacks in this initial profile.

## Acceptance

Use a real local OIDC provider with discovery, PKCE and signed ID tokens. Cover
wrong state/audience, replay, missing cookies, unknown account, profile mutation
attempts, provider/directory failures and two independent callback races. Verify
one exchange/session winner, safe restart-login response, explicit cleanup and
cancellation around late remote work. Test confidential-client authentication as
configured; public-client experiment evidence alone is insufficient.

Maintained TypeScript examples import genericOAuth from auth/better-auth. This
small forwarding export invokes the actual native factory and exposes its
supported id/options view without importing upstream types into public
declarations. Native callback verification and all cancellation acceptance remain
mandatory; the declaration boundary establishes neither.

Expose required route admission metadata, including the resolved database OAuth
state cookie from createCookieGetter(effectiveOptions)("state"). Test duplicate
state cookies across raw fields fail before native state consumption or provider
exchange, with custom role names and secure prefixes. The cookie-backed role
"oauth_state" is not a substitute for this selected database flow.

Prove the metadata URL binding, original-provider mutation, complete startup
gate and absence of request-time discovery through the exact native path.
Test two delayed JWKS requests from simultaneous callbacks: cancel one and
require the other to complete. Test body-stream cancellation and later retry
with a fresh login. Missing ID tokens must fail. Retain all previously listed
confidential-client, state-consumption, User lookup and late-commit tests.

Production TypeDoc for the integration factory and route policy must state that
all providers initialize before routes are returned, startup has no caller
cancellation or timeout guarantee, and `timeoutMs` applies to admitted routes.

## Prelinked Account and User lookup

Before exposing OIDC, add the native Account-to-User `findMany` shape: exactly
provider/subject equality, native base limit 2, one User by Account.userId and
an explicit `user` object or null. Use the canonical Account key and existing
User source. The unlinked/email path reuses the M10 User-to-Account read; native
signup and linking remain disabled. Other joined `findMany` calls remain
unsupported. Test absent Account, orphaned User, directory failure and the
unlinked branch with safe native outcomes, no session/cookie after failure and
no raw console or framework error logging. Separate indexed reads do not imply
a transaction. Preserve Verification consumption and cancellation tests.

The effective request is Account `findMany` with exactly providerId/accountId
string equality in either predicate order, `eq`/`AND`/sensitive comparison,
base `limit: 2`, and no offset, sort or selection projection. Its joined relation
is `user: { modelKey: "user", on: { from: "userId", to: "id" },
relation: "one-to-one", limit: 1 }`. The raw result is an array of Account fields
plus explicit `user: completeUserOrNull`. The canonical Account key normally
returns at most one match; retain the native two-match defense rather than
hiding inconsistent duplicates. This joined operation is unsupported until
implemented and verified in M11.
