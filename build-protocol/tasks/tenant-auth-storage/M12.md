# Tenant and authentication release acceptance

Final high-risk integration milestone. The complete TASK human ledger and
PROPOSAL acceptance checklist are binding; all earlier slices must be complete.

## Deliverables

Update narrow package references, generated API expectations, framework and
maintained example user guides to actual implemented APIs. Provide executable
examples for single-tenant and explicit multi-tenant assembly, a standalone
Gateway, combined process, direct native admission, component opaque/OIDC/signed
flows and every selected Better Auth profile. Explain optional record families,
external data sources, configuration, failure behavior, cleanup and shutdown.

Verify actual providers and separate-process persistence/concurrency; list
Datastore deployment indexes where required without claiming emulator tests prove
cloud deployment. Verify optional Better Auth imports/declarations and peer
metadata in installations with and without the optional library.

## Gates

After cheap preflight and the complete relevant independent review wave converge,
run verify:release once with the mandatory repository coverage threshold. Use
scripts-first diagnostics and return to focused checks for any failures; do not
weaken thresholds or use repeated full runs as diagnostics. Final security review
uses the existing security role at Sol/high. Resolve all accepted findings and
record every human-ledger disposition.

Keep detailed verification/review evidence outside Git. Retain only requirements,
decisions and maintenance-useful task links. Include the required version-only
commit for the feature branch, with internal pins/lock changes separate. Never
modify master, create or merge a PR, or publish packages without explicit
authorization. Push each feature-branch commit immediately to official origin,
as the current human-provided repository instructions require. Report
actual checks and material limitations; do not label incomplete gates as passed.
