# Explicit tenant selection

High-risk public-contract slice following M2. The complete Human-Imposed
Requirements Ledger in TASK.md and the accepted PROPOSAL govern this slice.

## Contract

Export `SINGLE_TENANT` as a unique symbol and `TenantIndexSetting` as its union
with `TenantIndex`. Keep `ServerEnvironmentSettings.tenantIndex` optional.
Omission and the explicit marker select single-tenant execution. Neither case
constructs a directory or calls a provider catalog.

Both environment and Bounded Context getters return the union. A single-tenant
Bounded Context always exposes the marker, including inside an environment
configured with a directory. A multi-tenant Bounded Context requires a real
environment index before it opens business handles. Its explicit index override
may then select another directory.

Remove `StorageTenantIndex`, `TenantIndexes.fromFactory`, and the inferred memory
directory. `PersistentTenantIndex` is the sole standard implementation. Keep
provider catalogs as provider APIs; their removal is outside this task.

Narrow the marker at admission, environment preparation/traversal, Stand,
application queries, native services and subscription paths. Preserve complete
TenantId routing and existing single-tenant rejection of named tenant IDs.
Use the captured effective selection consistently throughout an operation.

## Acceptance

- Omitted and explicit single-tenant settings never consult a catalog or index.
- Getter types force narrowing; maintained callers and public examples compile.
- Multi-tenant assembly without an environment index fails before business I/O.
- A single-tenant Bounded Context inside a multi-tenant environment returns the marker.
- Explicit index overrides and unknown-tenant admission retain their semantics.
- Existing eager/deferred business preparation, monitoring flags, environment
  create/check APIs, failure retry and shutdown behavior remain unchanged.
- Public documentation explains the default and the getter type change without
  presenting existing setting optionality as new.
