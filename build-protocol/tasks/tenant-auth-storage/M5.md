# Persistent OIDC login flows

High-risk protocol and one-time persistence slice. The complete TASK human ledger,
PROPOSAL and accepted architecture govern implementation. Auth remains independent
of ServerEnvironment and Bounded Context construction.

## Contract

Add OidcFlowStore and PersistentOidcFlowStore with separate domain-correct
transaction and application-grant records. Explicit flow identity qualifies the
keys. Use the standard private-constructor async factories, default preparation,
per-handle skip behavior and explicit close/cleanup contracts.

OidcFlow.start becomes async even in memory. Persist the transaction before
returning a usable authorization URL. Validate binding/proof/expiry before atomic
consumption. Consume a transaction before provider exchange and consume a grant
before application session issuance. Never restore consumed state after an
external failure. Independent instances must produce one winner.

Use openid-client 6.8.9 for discovery, authorization URLs and PKCE challenges,
and its underlying oauth4webapi 3.8.8 public request API for the token exchange.
Declare the latter directly. Retain mandatory jose ID-token verification and the
existing injected-clock key cache and shared-fetch cancellation. The high-level
openid-client grant snapshots a clock offset and cannot preserve these timing
semantics. Its raw request counterpart performs no identity verification; the
existing verifier must succeed before returning any identity.
Preserve discovery and explicit-metadata entry points, mandatory state/nonce/PKCE,
trusted issuer/redirect configuration, existing client authentication modes,
application fetch, response bounds, timeout and cancellation. General library
options must not disable required verification. Retain application identity
mapping and session issuance collaborators.

OidcFlow validates and consumes state before calling the existing provider
exchange port, which carries code, callback URI, verifier, nonce and signal.
Use code-only validated request parameters at that port, without adding a
synthetic state check. Send one token request with the exact callback URI,
including static query components. Preserve current signature/algorithm/key
policy, HTTP cache directives, unknown-key refresh and injected time sampling
after key loading. Do not replay a code or mutate process-global time.

Preserve the public discoveryEndpoint override, including URLs without a
`.well-known` path and URLs with query components. Scope its bounded fetch
wrapper to discovery, target the already selected default or explicit URL, and
explicitly compare the returned issuer with the trusted issuer before exposing
the provider. Immediately replace the returned Configuration's customFetch with
normal bounded application fetch through its public setter: discovery retains
its supplied wrapper. Do not reuse that endpoint override for token or JWKS
requests; test that the normal destinations are restored.
Before buildAuthorizationUrl appends flow parameters, remove every old value of
the protocol parameters currently replaced by OidcFlow; preserve unrelated
static query parameters. Test duplicate reserved keys and custom discovery
issuer mismatch.

## Acceptance

Test real HTTP discovery/token/JWKS exchanges and signed ID tokens; invalid issuer,
audience, nonce, state and PKCE; provider refusal/outage; identity mapping failure;
failed transaction/grant persistence; wrong browser proof preserving legitimate
state; cancellation before/after irreversible consumption; independent callback
and grant races; explicit indexed cleanup retaining concurrently changed rows.
Callback provider errors and pre-send cancellation produce zero token POSTs.
Token-endpoint refusal and validation failure after a response produce one;
cancellation at an arbitrary point produces at most one, with no grant retry.
No session is created after failed proof or failed identity mapping. Component
OIDC and Better Auth native OIDC are separate engines with separate records.

Keep public configuration examples and domain Protobuf documentation current.
This slice does not enable Better Auth or arbitrary new OIDC client-auth modes.
