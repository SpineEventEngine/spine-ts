# Browser credential and authentication routes

High-risk transport admission slice. The complete TASK human ledger, PROPOSAL
section 9 and accepted architecture govern implementation.

## Contract

Add a replaceable BrowserCredentialReader receiving immutable duplicate-preserving
headers, method and parsed URL, without access to the RPC body. Distinguish absent,
rejected and unavailable outcomes. Reject simultaneous credentials and legacy
cookies configuration.

Capture raw header multiplicity before WHATWG conversion. Reject repeated
Authorization, Origin and configured CSRF headers before any reader or auth route.
Inspect split Cookie fields and reject ambiguous authentication/CSRF cookie names
before combining permitted split fields. Apply the same policy to component,
external and Better Auth readers.

Admit exact configured auth route pathnames, retain callback query parameters,
forward every Set-Cookie separately and reject RPC route collisions. Preserve
route method, origin, body-size and deadline policies. Origin-less navigation is
limited to configured callbacks with protocol-state validation.

Use the verified cookie library for syntax. Preserve secure host-cookie and CSRF
invariants. Support the proposed SameSite/persistent settings; derive persistent
cookie expiry from the actual issued deadline. Rotation updates both credential
and CSRF cookies; deletion preserves cookie identity.

## Acceptance

Exercise actual HTTP hosting with duplicate raw headers, legal split cookies,
malformed and unavailable readers, callback queries, multiple Set-Cookie values,
route collisions and forbidden methods/origins. Document the standalone Gateway
configuration with no ServerEnvironment or Bounded Context construction.
