# Persistent tenant registration

High-risk slice following M1. The complete TASK human ledger and PROPOSAL apply.
Implement the tenant directory before changing environment defaults in M3.

## Contract

`PersistentTenantIndex` has a private constructor and async `create()`/`close()`.
It accepts the selected storage factory and group, optional default-true
`createMissingStructures`, and the established trusted clock seam. It requires
neither ServerEnvironment nor a Bounded Context to construct.

Use a domain-correct tenant registration Protobuf with complete TenantId and
first-registration Timestamp, following the inspected JVM Tenant meaning. Its
storage scope is single-tenant. Open an M1 non-preparing record handle; prepare
explicitly before returning unless false. Failed creation closes acquired
handles without closing the injected factory.

Registration uses absent-to-record compare-and-set. Repeated and concurrent
registration preserve the first timestamp. Contains uses a primary-key lookup.
Paging uses indexed keyset traversal, complete detached TenantId values,
existing finite request/cancellation semantics and instance-bound cursors.
`all()` traverses the complete directory without accidentally retaining a
provider's default result limit. No global snapshot is promised.

Close fences new work, drains admitted work and closes only the record handle.
Tenant registrations do not expire and have no purge API.

## Acceptance

- Full TenantId variants remain distinct; returned values cannot mutate storage.
- Independent factories register idempotently and preserve the first timestamp.
- Default/true prepares before returning; false emits no checks/DDL now or later.
- Incompatible structures reject construction; failure cleanup preserves factory use.
- Paging cancellation, invalid/cross-instance cursors and concurrent changes follow the contract.
- Multi-page all returns the complete list; page does not materialize the directory.
- Independent handle close and close during admitted work are deterministic.
- Actual provider durability and keyset behavior are exercised, not inferred from memory.
- New Proto messages/fields and TypeScript types/methods are documented; generated outputs remain ignored.

## Boundaries

M3 changes the public single-tenant marker/getter/assembly contract and deletes
inferred indexes. M2 must not change business-storage lifecycle or introduce
migration/provisioning behavior. Use the existing provider declaration and
preparation mechanisms; no generic persistence framework.
