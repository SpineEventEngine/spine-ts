# Session lifetime and local stream invalidation

High-risk admission and cancellation slice. The complete TASK ledger, PROPOSAL
sections 9–10 and accepted architecture govern implementation.

## Contract

SessionResolver.resolve accepts an optional operation lifetime. ResolvedSession
may expose an invalidated signal. Without a lifetime, retain no monitor. With a
lifetime, register before the authoritative read and release on rejection,
unavailability, operation end, expiry, invalidation and strategy close. Check
operation cancellation again before forwarding.

Use stable opaque session ID, scoped signed-token ID or authenticated Better Auth
session identity as appropriate. Admission and logout use the same integration
instance. Successful durable logout signals local streams before returning;
durable failure is still reported even if local forwarding was stopped.

SubscriptionGateway links the operation, expiry and shutdown signals and releases
resources in finally. Test actual stopped forwarding, not only signal state.
Already-sent bytes and already-admitted commands cannot be recalled. Shared
records do not provide cross-process invalidation or Gateway replication.

## Acceptance

Test logout during admission and after registration, normal stream completion,
backend failure, policy rejection, expiry and close. Verify no retained monitor
for one-shot resolution and no leak on any exit. Exercise standalone Gateway,
combined process and direct native admission using the actual public APIs.

## Native admission lifetime

DirectReaderAuthenticator.authenticate receives required host-managed request.signal
and returns ReaderAdmissionResult { reader, invalidated? } or undefined. Export both
public type names from the server root. Ingress snapshots reader facts and captures
invalidation separately; lifecycle signals never enter core trusted facts or proofs.
Use the one result shape directly for direct, forwarded and public admission.

Host lifetime starts before authentication and spans actual unary completion or
full activation iteration. Relay transport cancellation, returned invalidation and
shutdown; abort/release in finally even on normal completion with a live peer signal.
Subscribe retains a definition but releases its monitor; Activate authenticates
again and spans ACK/data output. Preserve principal binding and cancellation cleanup.
Coordinator must guard ACK/queued/dequeued output and child dispatch after async proof
work, cancel children via existing fan-out, and retain an independent cleanup signal.

A standard lifetime-aware resolver returns invalidation covering local logout, its
captured resolved expiry and strategy close. No lifetime retains no monitor/timer.
Use the existing clock and actual expiry, with no new TTL/poll/watchdog/cap; clock
failure stays fail-closed and platform timer bounds must not shorten validity.
Signed verification skew and revocation retention do not extend the returned
session deadline. Operation completion releases one monitor, not other sessions.
Close aborts monitors before draining short work. External native resolvers must
provide equivalent expiry/invalidation signaling to claim these guarantees.

## Additional native acceptance

Test actual native/Coordinator output and backend cancellation, register-before-read
logout races, already-aborted invalidation, paused filters/proofs and buffered output,
normal unary/stream completion, iterator return, callback/snapshot failure, shutdown
while admission is pending, and every monitor/listener/timer release. Mutable returned
facts or replacement signal properties must not change captured admission. Keep
forwarded proof semantics unchanged. Compile the public native assembly example.
