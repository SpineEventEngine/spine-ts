# Session lifetime and local stream invalidation

High-risk admission and cancellation slice. The complete TASK ledger, PROPOSAL
sections 9–10 and accepted architecture govern implementation.

## Contract

SessionResolver.resolve accepts an optional operation lifetime. ResolvedSession
may expose an invalidated signal. Without a lifetime, retain no monitor. With a
lifetime, register before the authoritative read and release on rejection,
unavailability, operation end, expiry, invalidation and strategy close. Check
operation cancellation again before forwarding.

Use stable opaque session ID, scoped signed-token ID or authenticated Better Auth
session identity as appropriate. Admission and logout use the same integration
instance. Successful durable logout signals local streams before returning;
durable failure is still reported even if local forwarding was stopped.

SubscriptionGateway links the operation, expiry and shutdown signals and releases
resources in finally. Test actual stopped forwarding, not only signal state.
Already-sent bytes and already-admitted commands cannot be recalled. Shared
records do not provide cross-process invalidation or Gateway replication.

## Acceptance

Test logout during admission and after registration, normal stream completion,
backend failure, policy rejection, expiry and close. Verify no retained monitor
for one-shot resolution and no leak on any exit. Exercise standalone Gateway,
combined process and direct native admission using the actual public APIs.
