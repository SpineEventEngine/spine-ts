## Staged Roadmap

### T-0016a Verification Gate Normalization

Acceptance criteria:

- `pnpm verify` works without manual tracked-file formatting workarounds.
- Verification has one normalized generation boundary for full checks. Nested
  scripts must not repeatedly publish generated output or race the same ignored
  generated directories.
- Formatting checks exclude ignored generated output and untracked human notes
  without requiring ad hoc shell workarounds.
- `proto:check-generated` compares against the same effective generation inputs
  used by the full verification command, so generated-clean evidence is
  meaningful.
- Verification reports coverage at or above 90%.

Likely files:

- `package.json`;
- `scripts/proto-workflow.mjs`;
- formatting, generated-clean, or verification helper scripts as needed.

Tests and checks:

- script tests for changed helpers;
- `pnpm verify`;
- generated-clean check.

Spine JVM inspection: not required because this is tooling-only.

### T-0016b Framework-Owned Generated Repository Assembly

Acceptance criteria:

- Ordinary app code no longer imports `HandlerMetadataRegistry` or
  `EntityHandlersMetadata`.
- Ordinary app code no longer hand-wires generated metadata into
  `new Repository(...)`.
- The to-do context uses a small framework-owned assembly API.
- The replacement API loads compiled generated registry modules through
  framework-owned discovery/ingestion and preserves the generated registry
  contract: declaration order, `parameterCount`, `emittedSchemas`, handler kind,
  and generated-message-only signal/return metadata.
- Public API docs, TypeDoc comments, package README, and user guides describe
  the new assembly API in the same task.

Likely files:

- `packages/server/src/context`;
- `packages/server/src/repository`;
- generated registry discovery/ingestion code;
- `examples/todo/src/index.ts`;
- public docs and API docs.

Tests and checks:

- context/repository tests;
- to-do tests;
- cleanup guard.

Spine JVM inspection: required. Start with bounded context and repository notes
under `spine-jvm-docs/`, then inspect relevant `core-jvm/server` source paths
when available.

## Simplification Risks

- `examples/todo/src/index.ts` still manually maps generated registry metadata
  into repositories. This is better than application-owned handler
  materialization, but still exposes more framework internals than the desired
  JVM-familiar app API.
- `Stand` keeps versions in memory.
- Delivery is storage-only rather than worker-integrated.
- Runtime routing still contains deferred query/subscription/system execution
  seams.
- Subscriptions are in-memory service state.
- Legacy compatibility exports such as `@Apply` and `defineEntityHandlers()`
  remain public, although docs and cleanup guards forbid them for ordinary app
  code.
