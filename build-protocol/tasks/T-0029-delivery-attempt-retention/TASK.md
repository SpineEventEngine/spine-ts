## Objective

Persist a small, framework-owned delivery attempt history for supported durable
endpoint failures, so later retry monitors can make policy decisions from
durable facts instead of only ephemeral `DeliveryRun.failures`.

## Scope

- Add an internal storage-backed delivery-attempt record path under
  `packages/server/src/delivery/`.
- Record attempts when a supported durable endpoint row produces a
  `DeliveryFailure`.
- Keep retained records bounded and sanitized: message/shard/inbox identity,
  label, node, attempted time, accepted flag, and stable failure stage/reason.
- Provide narrow package-internal read/query support for focused tests and
  future retry-monitor work.
- Keep failed inbox rows `TO_DELIVER`; do not change retry behavior.
- Update public docs/API docs to distinguish retained attempt history from
  retry policy, monitor callbacks, production supervision, topology, and
  production storage adapters.

## Out Of Scope

- Retry monitor policy, backoff, timers, scheduler ownership, or immediate retry.
- Public `DeliveryMonitor`, `FailedReception`, repeat-dispatch, or
  mark-delivered action APIs.
- Production worker/process supervision.
- ZeroMQ topology, broker lifecycle, remote/multi-host transport, or health
  policy.
- Durable catch-up storage, projection catch-up through inbox storage, or
  redefining `CATCH_UP`.
- New `IMPORT_EVENT` support.
- Public end-user delivery APIs.
- Production storage adapters, query planners, or storage capability
  negotiation.
- Raw payload/error retention, unbounded exception text, or stack traces.
