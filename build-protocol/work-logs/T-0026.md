## JVM Inspection Evidence

- JVM `Delivery.local()` uses single-shard synchronous local delivery with a
  deduplication window; `localAsync()` only changes dispatching to asynchronous
  local observer execution.
- JVM `Delivery.deliverMessagesFrom(shard)` picks a shard for the current node,
  runs delivery pages, releases the shard in `finally`, reports stats, and lets
  monitor actions decide repeats or pickup-failure behavior.
- JVM `LiveDeliveryStation` filters `TO_DELIVER`, deduplicates, sorts
  chronologically, dispatches to target delivery, and marks dispatched messages
  `DELIVERED`.
- JVM `TargetDelivery` routes stored rows through command/event inbox endpoints
  and reports failed reception to `DeliveryMonitor`; it does not expose
  framework envelopes to application code.
- JVM `ServerEnvironment.delivery()` defaults to local delivery and stores the
  configured delivery in process-wide environment state.
