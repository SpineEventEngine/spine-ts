## 2026-08-03 — Root cause

- Reproduced the lifecycle from source: the local fixture resolves a session
  that expires after 60 seconds; the gateway closes `Activate` at that expiry;
  the browser client reconnects but retains the retry count and retry start
  time across healthy replacement generations. Repeated expiry therefore
  exhausts the historical retry budget and ends live updates while unary
  command posts remain available.
- Confirmed that MessageBoard has stable React subscription dependencies and
  does not use `StrictMode` in its local entry point. The additional `Activate`
  calls are recovery generations, not render-driven duplicate subscriptions.
- Ran the requirements splitter with the explicit configured
  `gpt-5.6-sol`/high profile. Runtime self-introspection was unavailable. The
  planning pass did not return within the bounded planning window and was
  interrupted without accepting output or code. Repository evidence is
  sufficient for the following narrow implementation decision.
- A replacement stream that remains connected for at least the configured
  retry `maxElapsedMs` starts a fresh retry episode on its next failure. Streams
  failing faster remain in one finite episode and still exhaust `maxAttempts`
  or `maxElapsedMs`. The local fixture session will use a practical development
  lifetime so routine local use does not create minute-by-minute renewal RPCs.

  `pnpm typecheck:build:generated` passed in the isolated worktree.
