## Decisions

- Start from the current small `Server` lifecycle API and add an explicit
  environment assembly object rather than introducing a Java-style global
  singleton.
- Keep ZeroMQ endpoint topology and worker execution out of this slice; the
  environment should only expose the ownership boundary needed by `T-0017l`.
- Keep local/test defaults convenient. Require explicit storage and transport
  only for production-mode environment construction.
- Use the existing `StorageFactory` and `SignalTransport` contracts rather than
  introducing a new transport-factory abstraction before T-0017l defines
  production endpoint topology.
- Treat omitted server environments as server-owned local/test defaults.
  Supplied environments are caller-owned by default and only closed by the
  server when `ownsEnvironment: true` is explicit.
