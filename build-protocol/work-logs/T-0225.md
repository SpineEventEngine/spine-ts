## Root cause established before implementation

- Build-time analysis accepts Command, Event, and rejection inputs for
  `@Command`, but represents all three as `command-reaction`.
- Runtime command readiness and repository command routing register only
  `command-assignment` handlers.
- Runtime event routing registers every `command-reaction`, so command-input
  methods are attached to the wrong bus.
- The public service therefore sees no accepted command type and reports
  `UNSUPPORTED_COMMAND`; server-context posting has the same missing dispatcher.
- Existing tests cover analysis/ingestion and event-to-command execution but do
  not exercise command-to-command delivery end to end.
