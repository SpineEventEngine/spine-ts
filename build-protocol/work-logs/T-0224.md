## Contract and implementation

- `MessageId` represents a generated Buf `Message`.
- The target Entity ID field supplies the schema used for admission.
- Generated validation runs before durable serialization.
- `Identifiers.pack()` verifies that the complete message is serializable.
- Default Command routing reads the Command's declared first field.
- Event routing prefers a compatible packed producer ID and otherwise reads the
  Event's declared first field.
- State-update routing selects the first state field compatible with the Entity
  ID field.
- Custom routes retain complete message IDs or return a compatible primitive ID
  for a primitive target.
- Inbox targets, persistence keys, producer contexts, route deduplication, and
  dispatch guards continue through descriptor-aware packed identity.

## Cross-repository Event fan-out result

The final private `packages/server-blackbox-tests` workspace contains three
state-based project-management scenarios. The `Project` Aggregate handles a
real `CreateProject` Command and emits a real `ProjectCreated` Event.
`ProjectPlanning` and `ProjectStaffing` are separate reacting Process Manager
types with separate `PlanningId` and `StaffingId` messages and separate custom
routes. `ProjectCoordinator` is a commanding Process Manager that deliberately
uses the producer's composite `ProjectId`, receives the Event through default
producer routing, and returns a real `ScheduleProject` Command. The Project
handles that Command, emits `ProjectScheduled`, and records the scheduled
status in its persisted state.

`Portfolio` is a Projection with a separate `PortfolioId` and custom route.
`ProjectProjection` deliberately uses `ProjectId` and default producer routing.
Every identifier is a generated composite Protobuf message containing a nested
`OrganizationId` and an integer field. Thus, only Entities whose declared
routing semantics require the producer ID share the producer's ID type.

The direct positive and negative tests read exact persisted Entity states from
`Stand`. The additional BlackBox test posts `CreateProject` through a public
BlackBox scope and reads all six states with public Queries. No test posts an
Entity state as a Command, reuses a logically unrelated Protobuf message, or
treats Inbox rows or mutable counters as the result.

The negative scenario gives only `Portfolio` an exact custom route returning
no targets. Its state remains absent while the Project, all three Process
Managers, and `ProjectProjection` reach their exact expected states.

The private workspace uses only public package exports. Its local descriptor
fixtures contain only the declarations needed by the scenario. Package,
Lerna, artifact, and architecture-boundary policies distinguish public
manifests from this private workspace and keep the release inventory at exactly
18 packages.
