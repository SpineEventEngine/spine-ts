## Third Slice — Recovery Generation Guard — 2026-08-06

- Added example-local generation semantics to `useBoardSync`. Every applied
  valid live batch advances the local update generation. Each `refresh()`
  request captures that generation plus its board identity and may replace rows
  only while both are still current.
- A valid live batch arriving during an in-flight recovery marks the older
  response stale and requests one coalesced follow-up query. Multiple batches
  collapse into that one follow-up through the existing request counter.
  Board-switch and unmount cleanup invalidate both refresh and update
  generations and abort active recovery work.
- Added deferred-query React tests for a live batch racing an older recovery,
  multiple live batches coalescing to one follow-up query, board-switch stale
  completion, and unmount stale completion. The first race tests failed before
  implementation because the old recovery replaced live rows and issued no
  follow-up query.
- Final focused evidence: 49/49 tests pass across `message-board.test.tsx`
  and `board-payloads.test.ts`; web TypeScript typecheck, changed-production
  ESLint, Prettier, and `git diff --check` pass.
- Limitation and next slice: connected/disconnected successful-post behavior
  and browser smoke remain intentionally out of scope.
