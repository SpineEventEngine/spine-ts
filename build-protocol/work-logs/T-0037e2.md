### Current TypeScript ownership and lifecycle evidence

- Inspected `packages/server/src/delivery/delivery-run-coordinator.ts`,
  `packages/server/src/server/environment-attachment.ts`,
  `packages/server/src/server/environment-delivery-worker.ts`,
  `packages/server/src/server/environment-delivery-records.ts`,
  `packages/server/src/server/server-environment.ts`, and
  `packages/server/src/context/local-inbox-handoff.ts` before shaping the new
  transition.
- `EnvironmentAttachments` is the existing deep package-internal lifecycle
  module and serial admission seam. Its single `#serial` queue orders attach,
  detach, failed-start retry, and detach retry. It owns cardinality claims,
  opaque handles, the generation map, and durable failed rollback/last-detach
  state. This is the smallest location for the sole reusable-stop operation;
  bypassing it through server/handoff code would split admission ownership.
- `DeliveryGeneration` currently owns its worker, coordinator, live
  registration states, per-registration `RegistrationReadiness`, descriptor and
  tenant runtimes, canonical `EnvironmentDeliveryRecords`, overlap domains,
  and reported failures. `EnvironmentRegistrationClaim.generation` and the
  returned attachment handle are immutable old-generation identities today;
  reusable stop therefore needs an internal rebinding indirection rather than
  mutating or replacing public/returned handle values.
- `DeliveryReadiness.transition()` is a one-way direct-to-routed handoff with
  bounded buffering while direct claims settle. `RegistrationReadiness` is a
  separate registration-local waiting/open/failed bridge. Existing descriptor
  readiness routes close only by invoking each descriptor transition; writes
  during that transition buffer there, while writes after routing but before
  registration readiness opens buffer in `RegistrationReadiness`.
- `EnvironmentDeliveryRecords` is generation-local and owns configured scope
  order plus registration/generation/shared parked obligations. Existing
  `retire()` consumes all ownership, while non-last `detach()` and failed-start
  `rollback()` intentionally remove narrower ownership. Reusable stop cannot
  call `retire()` before survivor state has been captured by a bounded
  transition owner, and scope transfer must preserve the existing canonical
  order without route-rebinding the scope values.
- `DeliveryRunCoordinator.retire()` is externally retryable. It closes
  admission and calls stop once, retries quiescence until proved, then attempts
  report and permanent worker retirement, marks `#finalized = true`, and only
  then propagates accumulated post-quiescence failures. Consequently
  `replacementSafe` is false for stop/quiescence failure and true for report or
  inert-retirement failure. The coordinator is permanently inert whenever
  replacement-safe, even when `retire()` rejects.
- Existing failed-start and detach retry states are opaque module-owned objects
  with stable progress flags and shared in-flight promises. Reusable stop should
  follow this precedent: one module-owned operation record, external retry of
  that record, no timer/background recursion, and no caller-visible retry
  token. It must remain distinct from `#failedRollback` and
  `#failedLastDetach`, which T-0037e1 already owns and this task must not reopen.
