## Cross-Example Producer-ID Correction

- Focused delivery instrumentation proved the healthy local shard fence is not
  the failure: every observed `ShardedWorkRegistry.validateOwnership()` result
  remained defined. The aggregate handler executes, then Event history rejects
  the produced event with `Event history requires an EventContext producer ID.`
- The exact source was `RepositorySignals.runtimeProducerId()`: it only reads
  finite scalar IDs. The MessageBoard and To-Do aggregates use generated
  message-valued IDs, so their otherwise accepted produced events had no
  producer ID when the current entity-history contract validated them.
- The bounded repository correction now packs the actual repository ID field
  into every Aggregate and Process Manager produced-event context. It leaves
  `SignalMetadata`'s scalar input and rejection behavior unchanged.
- RED/GREEN evidence: the new MessageBoard message-ID EventStore regression
  failed before the correction and passes after it; the established scalar
  producer-ID repository regression also passes. The original projection
  subscription timeout remains a separate downstream delivery issue to trace.
