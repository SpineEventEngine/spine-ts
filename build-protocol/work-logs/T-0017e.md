## Decisions

- This slice is limited to generated `@Command` and `@React` handler execution
  and framework-owned wrapping of produced domain messages.
- Process-manager runtime execution, durable inbox handoff, delivery scheduler
  loops, and transport-backed worker execution remain deferred to later
  roadmap slices.
- Keep TypeScript runtime user handlers domain-message oriented: handler APIs
  receive domain messages plus optional command/event context and return domain
  messages; buses/repository adapters construct framework `Command`/`Event`
  envelopes internally.
- Generated registry ingestion now preserves emitted schema metadata for
  producer handlers and rejects missing emitted schemas for generated
  `@Assign`, `@Command`, and `@React` records. Generated `@Subscribe` remains
  void-only and rejects emitted schemas.
- Aggregate event intake now executes generated event-side `@React` handlers
  that return domain events and generated event-side `@Command` handlers that
  return domain commands. Returned events are wrapped with producer ID, version,
  and `past_message` origin derived from the source event. Returned commands are
  wrapped with command IDs derived from the source event plus
  `CommandContext.origin` derived from the source event ID/type URL, source
  actor context, and source grand origin when present.
- Produced domain messages are dispatched only after handler transaction and
  storage work succeeds. Produced command dispatch uses the context command bus;
  produced event redispatch is scheduled as event-bus follow-up work appended
  to the active runtime queue, drained before close, and ordered before later
  external posts.
- Generated emitted schemas are framework-owned metadata, not public handler
  record fields. Runtime code reads them through `handlerMetadataAccess`.
- Managed/no-applier aggregate event execution rejects unsnapshotted history,
  mirroring command execution.
- No process-manager execution, durable inbox handoff, scheduler loop,
  transport-backed worker, schema-bearing decorator API, `@Apply`, app-owned
  materialization, framework envelopes in user handler signatures, or manual
  end-user transactions were added.
- Public decorator docs now describe `@Assign`, `@Command`, `@Subscribe`, and
  `@React` as bare-only. Schema-bearing handler metadata is generated/internal
  tooling and framework materialization state only.
- Bounded context shutdown now closes public command and event intake first,
  then drains command and event bus runtimes to cross-bus quiescence while
  framework-owned produced commands and stored-event dispatches may still
  enqueue internal follow-up work. Final bus/resource close happens only after
  that drain loop stabilizes.
