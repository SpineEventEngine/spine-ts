## Implementation Notes

- `2026-07-09`: Added `DeliveryLoop` in
  `packages/server/src/delivery/delivery-loop.ts` and exported
  `DeliveryLoop`, `DeliveryLoopOptions`, `DeliveryLoopRun`, and
  `DeliveryLoopStatus` from `@spine-ts/server`. The loop repeats
  `Delivery.drain()` for one configured shard/node until a drain is idle, the
  shard claim is skipped, `stop()`/`close()` is requested, or the configured
  `maxFailures` bound is reached. `close()` stops future drains and awaits the
  current drain. No new durable retry storage, attempt history, catch-up
  storage, conveyor, station, or monitor hierarchy was introduced.
- `2026-07-09`: Added focused tests in
  `packages/server/test/delivery/delivery-loop.test.ts` covering multiple
  pages and late rows, retry on a later loop run after a failed row remains
  `TO_DELIVER`, skipped shard reporting, stop-before-run, close waiting for an
  in-flight drain, and the failure bound. Updated the server root export guard
  and `scripts/check-api-docs.mjs` for the new public surface.
- `2026-07-09`: Updated `packages/server/README.md`, `docs/USER_GUIDE.md`,
  `docs/api/README.md`, and `docs/architecture/README.md` to describe the
  supported loop/retry/shutdown semantics and to keep catch-up honest as the
  existing `BoundedContext.catchUpReadSide()` coordination path without fake
  durable catch-up storage.
