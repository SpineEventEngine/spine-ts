## JVM Research

- `2026-07-08`: Inspected local `core-jvm/server` subscription code before
  implementation:
  - `io.spine.server.SubscriptionService`

  - `io.spine.server.stand.TopicValidator`
- JVM `EntityChangeHandler` handles ordinary entity state changes by checking
  target type, then:
  - delivers a packed new state for `include_all`;
  - for filtered topics, first requires the entity ID to match;
  - delivers a packed new state if the new state matches filters;
  - delivers `EntityStateUpdate.no_longer_matching = true` if the new state no
    longer matches but the old state did.
- JVM `UpdateHandler.idMatches()` treats a missing ID filter as matching all
  IDs and otherwise compares the packed entity ID against `TargetFilters.id`.
- `proto/spine/client/subscription.proto` confirms `Topic.field_mask` applies
  to delivered entity states and `EntityStateUpdate.kind` is either `state` or
  `no_longer_matching`.
- `proto/spine/client/filters.proto` confirms queries restrict field filters to
  columns, while subscriptions may use arbitrary message fields including
  nested fields. This task should not reuse the query-only column restriction
  for subscription matching.

## Decisions

- Keep T-0017c in the existing direct Stand/service architecture. Do not add an
  event tap, durable delivery scheduler, or new transport layer for this slice.
- Extend the direct `StandUpdate` contract with an optional previous state read
  from storage inside `Stand.update()` before writing the new state. This gives
  the service enough information to reproduce JVM no-longer-matching semantics
  without introducing system-event plumbing prematurely.
- Implement subscription matching inside `SpineServices` activation delivery,
  because `Topic` is a service/client contract and direct `Stand.subscribe()`
  should stay a small in-process state-update API.
- Support subscription filters over generated TS local field names resolved from
  proto field paths, including nested paths, and compare decoded primitive
  values plus generated message objects. Unsupported composite or comparison
  operators fail deterministically during `Subscribe`, before Stand listeners
  are attached.
- Apply `Topic.field_mask` to cloned delivered states only. Do not mask
  `no_longer_matching` updates because they carry only the entity ID and flag.
