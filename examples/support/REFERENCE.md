# Support example reference

The domain Protos in `proto/spine/examples/support` define a ticket Aggregate, a drafting Agent, and a review Projection. `SupportTicketId` identifies both the ticket and the Agent. `DraftSupportReply` carries the current facts and an explicit `ConversationId`. The application does not infer a conversation from the ticket ID.

[model.ts](src/model.ts) exports `draftSupportReply`, an `AiModel.define()` operation with typed `DraftSupportReply` input, typed `SupportReply` output, validation, and configured request bounds. This definition is imported by both [SupportDraftAgent](src/support-domain.ts) and `SupportContext.create()`. The Bounded Context registers it through `.add(SupportDraftAgent, { ai: { models: [draftSupportReply] } })` and installs the deployment registry through `.withAi(ai)`. The framework resolves the definition by Agent state type, operation name, and revision. `ModelRef` identifies a provider deployment, separately from this operation definition. The application provides the registry and credentials outside the Agent.

`SupportDraftAgent.draft()` is an `@Command` handler. It saves current facts and conversation, then returns `this.modelCommands.create(draftSupportReply, { conversation, input: command })`. Creation contacts no provider. The returned `CallModel` is saved in Agent history and its call ID enters `pendingModelCalls` with the Agent commit. After that commit, the Agent publication path records the complete submission attempt and posts the Command. The framework `AsyncCommandHandler` then executes the pinned deployment. The Agent's original Inbox row becomes `DELIVERED` after its handler and save complete, while the provider may still be running.

The Agent's `@React` handlers receive `ModelReplied` or the `ModelCallFailed` rejection. They use `modelCallHistory(callId)` to read the complete original draft Command and compare its facts and conversation with the current Agent state. A late result for replaced facts is handled without producing a stale proposal. A current valid reply emits `SupportReplySuggested`; a current failure emits `SupportReplyFailed`. Those domain Events retain the facts, conversation, and typed model call ID. The review Projection clears a prior draft when its facts or conversation are replaced. It does not send an email or a reply.

`BlackBox.readAgentHistory(SupportDraftAgent, ticketId, ...)` reads indexed full history using the typed `SupportTicketId`. Full history includes prepared model requests with complete Command and triggering envelopes, submission attempts, provider exchanges, handled outcomes, domain Events, and System Events. Conversation history returns provider exchanges only. A saved pending call or history entry is not a startup execution queue. If the original input remains `TO_DELIVER` after interruption, ordinary redelivery may run its handler again and create a new call ID. A saved call is never automatically resubmitted after restart.

The [BlackBox test](test/support-blackbox.test.ts) covers typed success, malformed output, a corrected reply, changed facts, and an older reply arriving after newer facts in the same conversation. It uses `AiTestBackend` without a paid model request. The memory provider retains records only for its process; applications that need durable tickets, drafts, and history configure persistent storage.
