# Support example reference

The generated domain Protos are under `proto/spine/examples/support`. `types.proto` defines `SupportTicketId`, supplied `SupportRequest` facts, and reviewable `SupportReply`. `commands.proto` keeps ticket opening and reply drafting distinct. `events.proto` records ticket opening, proposal, and failure. `states.proto` declares the ticket Aggregate, drafting Agent, and review Projection with the canonical Spine Entity kinds. Every draft Command and outcome carries `spine.ts.agent.ConversationId` supplied by the application; no conversation is inferred from a ticket ID.

The first field of each Entity state is its ID. The runtime requires that ID and validates the ID message through the repository, so these state fields omit redundant `(required)` and `(validate)` options. This convention does not make arbitrary message fields required or recursively validated.

`src/model.ts` defines one generation capability with two physical model-request credits, no tools, a 30-second deadline, and byte and token bounds. The instructions use reported facts, recognize the already attempted restarts, and prohibit an invented diagnosis or resolution claim. `SupportDraftAgent` awaits `this.ai.invoke` from its `@Assign` handler. A usable result updates its draft and returns `SupportReplySuggested`; a failed operation returns `SupportReplyFailed` and does not overwrite the Agent's previous accepted draft. Both Events retain the submitted facts, conversation, and operation identity. `SupportReview` preserves any earlier accepted reply on failure and marks the latest request as failed. Nothing sends an email or reply.

`SupportContext.create(registry, storage?)` assembles generated repositories with `withGeneratedRegistryRoot`, installs the provided `AiRegistry`, persists System Events, and registers the ticket, Agent, and Projection. Its caller supplies an authenticated deployment registration and a default generation model. The BlackBox test uses `AiTestBackend` for that registration. Production configuration must register an actual permitted adapter and credentials through its provider's supported secret mechanism; the example intentionally contains no placeholder credential flow.

The BlackBox audit read names `SupportDraftAgent` and a typed `SupportTicketId`. The box resolves that class against its Bounded Context's generated repository registration; TypeScript rejects a different domain ID at the call site.

A posted Command can return `ok` before its Agent finishes. The accepted Agent invocation retains the original signal, selected handler binding, saved model request and result, bounded counters, and outcome. A successful reply is a domain Event for human review. Framework System Events and conversation content remain separate audit records. The retained history offers four indexed views: full, a specified conversation, System Events, and domain Events. Pages are newest first; use the returned cursor to continue toward older records. The BlackBox `readAgentHistory` convenience reads the full view. Provider storage must keep accepted history; the example's memory provider keeps it for this process only. Choose a persistent provider for a durable deployment.

`SupportTicketId` is the typed ID in both the ticket Aggregate and Agent. The explicit conversation is scoped to that Agent instance and may continue on a later request. The support reply state and Event preserve exactly which facts produced a draft. Reposting a new Command starts new work; retrying delivery of the same accepted signal uses the recorded result under the framework's claim fence. Saved downstream output can be retried, so consumers should use domain IDs for idempotent effects. The example performs no external effect.

The test entrance is `BlackBox`: it posts `OpenSupportTicket` and `DraftSupportReply`, waits for the resulting domain Event, queries `SupportReview`, and reads retained Agent audit using the Agent class and its typed identifier. The valid scripted response demonstrates typed output. Malformed scripted output demonstrates failure without a reviewable draft. A blank typed reply followed by a correction exercises the domain validation rule. Provider crash, concurrent-claim, and MCP protocol behavior are outside this application example's tests.
